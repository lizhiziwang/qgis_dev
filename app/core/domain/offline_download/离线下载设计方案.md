# 离线下载（offline_download）设计方案

> 阶段定位：本方案先行。领域包 `app/core/domain/offline_download/` 先落设计，
> 后续按「阶段二 → 阶段四」逐步落地代码（见文末《落地阶段》）。
> 本文档同时承载领域包的**接口契约**与 **TaskInfo 模型**定义，实现时按此对齐。

---

## 1. 背景与目标

外业（无网络/弱网）场景下，核查人员需要把当前任务涉及的图层数据整体下载到
本机，断网后仍能打开、浏览、编辑、核查图斑，回到网络环境再回传结果。

一次「离线下载」=

1. 用户在弹窗里选定 **任务 + 空间范围 + 需要的图层**；
2. 程序从**任务信息**里取到各数据集的服务地址，按空间范围抓取数据；
3. 数据按规范落盘并打成**一个压缩包**：
   - 矢量 → 打进 **FileGDB**（.gdb）；
   - 影像 → 按数据集**分别建文件夹**存放；
   - 属性模版/规则包/字典等文件类数据 → 直接按数据集文件夹存放；
4. 附带**离线清单 manifest.json**（每个数据集的来源地址、时相、范围、大小、
   校验和），供「下载管理」与后续「离线包导入/回传」使用。

## 2. 术语与数据集清单

| 数据集 | 是否必选 | 类型 | 说明 | 落盘去向 |
|---|---|---|---|---|
| 图斑矢量 | 必选 | 矢量 | 任务图斑（核查对象），来自任务信息**图斑矢量服务地址** | `矢量.gdb/图斑` |
| 属性模版 | 必选 | 文件 | 制图/建库属性模板 | `文件/属性模版/` |
| 规则包 | 必选 | 文件 | 质检规则包 | `文件/规则包/` |
| 字典 | 必选 | 文件 | 属性字典/码表 | `文件/字典/` |
| 前时相影像 | 可选 | 影像 | 变化前时相 | `影像/前时相/` |
| 后时相影像 | 可选 | 影像 | 变化后时相 | `影像/后时相/` |
| 本底数据 | 可选 | 影像 | 本底影像/底图 | `影像/本底数据/` |
| 政区边界 | 可选 | 矢量 | 行政区划边界 | `矢量.gdb/政区边界` |
| 参考矢量 | 可选 | 矢量 | 参考矢量层 | `矢量.gdb/参考矢量` |
| 参考影像 | 可选 | 影像 | 参考影像 | `影像/参考影像/` |

> 「属性模版/规则包/字典」当前在任务信息里以**地址**形式存在；若地址指向服务
> 数据（而非单个文件），见 6.2 的来源类型（`service` vs `file`）路由。

### 2.1 时相（前后景）

「前时相影像 / 后时相影像」来自任务信息的**前后景时相影像服务地址**，可能是：
- 两条独立地址（前/后各一）；
- 一条含多时相（`scenes` 列表）的地址。

TaskInfo 用 `list[ImageryItem]` 表达（可承载多条时相），且每个条目保留
`phase="before"/"after"` 标注。下载时每一条时相独立成文件夹
`影像/<phase_标签>/<scene名>/`，避免同名覆盖。

## 3. TaskInfo 任务信息模型

> 仓库目前没有「任务信息」结构，任务信息来自平台服务端（JSON）。在领域包内
> 定义只依赖标准库的 `TaskInfo`，由 `from_dict()` 反序列化；UI/下载流程只面向
> 该模型。后续接入真实服务时只需保证返回 JSON 字段可被解析。

```python
# app/core/domain/offline_download/task_info.py  （契约草案）
from __future__ import annotations
from dataclasses import dataclass, field
from typing import Optional

@dataclass(frozen=True)
class DataSource:
    """单个数据集来源：优先取服务地址；也可直接给文件/文件列表地址。"""
    name: str                 # 数据集名称（中文字段/目录名，去重后用作落盘名）
    service_url: Optional[str] = None   # 服务地址（ArcGIS REST / WMS 等）
    file_urls: tuple[str, ...] = ()     # 直接文件下载地址（属性模版/字典等常用）
    #: 服务内子图层 id / 图层名（FeatureServer 常有多个图层）
    layer_id: Optional[str] = None
    #: 影响估算与抓取策略的提示（见 6.2），缺省由 URL 形态自动推断
    source_type: Optional[str] = None   # "arcgis-feature" / "arcgis-image" / "wms" / "file" / "auto"

@dataclass(frozen=True)
class ImageryItem:
    """一条时相影像。"""
    phase: str                          # "before" | "after" | "baseline" | "reference" ...
    name: str                           # 时相标签（如 2024-06-12）
    service_url: Optional[str] = None
    file_urls: tuple[str, ...] = ()

@dataclass(frozen=True)
class SpatialExtent:
    """任务空间范围（矩形外包）。来源=任务 JSON 字段（含坐标系），与画图斑无关。"""
    xmin: float
    ymin: float
    xmax: float
    ymax: float
    crs: str = "EPSG:4326"          # extent 所在坐标系；规划抓取前转目标数据源 CRS

@dataclass(frozen=True)
class TaskInfo:
    """任务信息：全部下载数据源的地址都从这里取。"""
    task_id: str
    task_name: str
    #: 任务下发的空间范围（任务 JSON 里的字段）。「全部空间范围」取这里——
    #: **不从图斑矢量几何并集推算**：即使任务还没画图斑，该字段也应有值，范围不空。
    task_extent: Optional[SpatialExtent] = None
    features: DataSource                        # 图斑矢量（必选，本方案强约束非空）
    attr_template: Optional[DataSource] = None  # 属性模版
    rule_package: Optional[DataSource] = None   # 规则包
    dictionaries: tuple[DataSource, ...] = ()   # 字典（可多个）
    imageries: tuple[ImageryItem, ...] = ()     # 前/后时相等全部影像条目
    basemap_data: Optional[ImageryItem] = None  # 本底数据
    admin_boundary: Optional[DataSource] = None # 政区边界
    reference: Optional[DataSource] = None      # 参考矢量/影像（服务地址+layer 判断）
    # 可扩展：crs/auth/token、样式 qml 地址、工作目录……

    @classmethod
    def from_dict(cls, d: dict) -> "TaskInfo": ...
    def to_dict(self) -> dict: ...
```

**约定**
- 字段可空表示「任务无该数据」，UI 对应勾选框置灰。
- 空值是**“该任务没有”**，与「有但用户不下载」区分开——后者由请求（DownloadRequest）控制。
- 政区边界 / 参考矢量 / 参考影像可能共用一张表，用 `DataSource.source_type` +
  `layer_id` 区分矢量/影像；源类型不确定时填 `auto`，运行时按 URL 形态推断：
  - `/FeatureServer…` → `arcgis-feature`（矢量）；
  - `/ImageServer…` 或 `/MapServer…` → `arcgis-image`（影像/动态出图，除非另有
    FeatureServer 端点可取矢量）；
  - `wms` / `wmts` → 对应 OGC 影像；
  - 其它 `http(s)` 直链 → `file`（普通文件，HEAD 取长度）。
- `from_dict` 对**未知键宽容**（忽略不报错），平台后续新增字段不破坏解析；
  反序列化器统一放 `task_info.py`，UI/下载流程只见模型。
- TaskInfo 预留扩展位（`crs`、`auth`、`style_qml_urls`、`default_zoom` 等），
  本方案未用到的字段先不定义，后续平台给到再按“可选键”补。
- `task_extent`（任务空间范围）的 JSON 键名与坐标系由平台下发约定（常见 `extent`
  或 `scope_extent`，多数直接给外包矩形），`from_dict` 适配并把数据统一落入
  `SpatialExtent`；**它是“全部空间范围”的唯一来源**，不是从图斑几何推算。

## 4. 界面与交互（图斑核实平台主界面）

弹窗：**「下载离线图层」**（按钮：工具 dock / 工具条「离线下载」）。

```
┌─ 下载离线图层 ───────────────────────────────────────────────┐
│  选择任务   [任务下拉 ▲]                                       │
│  空间范围   (●) 全部空间范围   ( ) 视图范围   ( ) 框选范围       │
│  ───────────────────────────────────────────────             │
│  下载图层（每个数据集独立一行）                                 │
│  ☑ 图斑矢量（必选）                     …约 12 MB             │
│  ☑ 属性模版                           …约 0.5 MB             │
│  ☑ 规则包                             …约 1 MB               │
│  ☑ 字典                               …约 1.5 MB             │
│  ── 可选（任务没有该数据则整行置灰） ──                          │
│  ☐ 前时相影像 [2024-06]                …约 90 MB              │
│  ☐ 后时相影像 [2024-12]                …约 90 MB              │
│  ☐ 本底数据                            …约 20 MB              │
│  ☐ 政区边界                            …约 30 MB              │
│  ☐ 参考矢量                            …约 5 MB               │
│  ☐ 参考影像                            …约 10 MB              │
│  ───────────────────────────────────────────────             │
│  下载位置   D:\外业数据\  [浏览…]      剩余 123.4 GB            │
│  数据估算   已选约 212 MB（含冗余系数 1.3）                      │
│  ───────────────────────────────────────────────             │
│  ▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░  下载进度 30%  当前：后时相影像      │
│  ───────────────────────────────────────────────             │
│              [下载管理]              [取消]  [开始下载]         │
└──────────────────────────────────────────────────────────────┘
```

要点：

1. **选择任务**：当前打开的工程/已加载任务；切换任务时重拉该任务 TaskInfo，
   刷新图层勾选区与估算。任务来源后续对齐平台接口，现阶段用 TaskInfo JSON
   （工程里已加载的「任务」或示例数据）填充。
2. **空间范围** 三选一（默认**全部空间范围**）：
   - **全部空间范围** = 任务**字段中的空间范围**（任务 JSON 里的 `task_extent`，
     任务下发的作业/覆盖范围），**不是图斑矢量几何并集**——任务还没画图斑时该
     字段依然有值，范围不会空；
   - **视图范围** = 当前地图画布可视范围：`canvas.mapSettings().extent()`（而非
     裸 canvas.extent()，二者含变换上下文差异），实时取值；
   - **框选范围** = 用户在画布上拖框选择：新建一个 `QgsMapTool`（矩形 rubber
     band），参照 `app/ui/tools/select_feature.py` / 绘制交互现成范式；拖完把
     rubber band 外包矩形回传弹窗；
   - **CRS 统一**：范围取值先归一到主界面当前画布 CRS，抓取前再经
     `QgsCoordinateTransform` 换算到**数据源自身 CRS** 用于裁剪/过滤——全部用
     代码里现有坐标变换工具，不手写投影公式；
   - **兜底**：任务 JSON 未给 `task_extent`（历史任务/字段缺失）且未画图斑时，
     “全部空间范围”无意义——开始下载前明确提示改用视图/框选，不静默全幅下载。
3. **下载图层 = 勾选列表，每个选项占一行**：做成「数据集勾选列表」（每行一个
   `QCheckBox`，左右布局：勾选框+数据集名/时相在左，该项估算大小右对齐），
   而不是一行塞多个勾选框。行划分（自上而下）：
   - **必选组**：图斑矢量、属性模版、规则包、字典——默认勾选且禁止取消（置灰
     的勾选状态）；任务没有的数据仍不出现；
   - **可选组**（“可选”分隔条之下）：前时相影像/后时相影像/本底数据/政区边界/
     参考矢量/参考影像——默认不勾；任务无该数据时整行置灰禁用；
   - 行尾估算大小随勾选变化即时重算合计；列表超高时包进可滚动区域
     （`QScrollArea`），行数不影响弹窗高度。
4. **磁盘与估算**：显示目标盘剩余空间与估算总大小（见 7），并做预检：
   `估算 × 冗余系数 > 剩余空间` → 禁止开始下载并提示。
5. **下载进度条（按钮行上方）**：形态与位置参照 `app/ui/dialogs/buffer.py`
   的“进度条 + 底部按钮”组合——一根横向 `QProgressBar`，`setRange(0, 100)`、
   占满宽度、紧贴底部按钮行上方；进度条右侧/行内带一行状态文字（如
   `下载进度 30%  当前：后时相影像`）。
   - 驱动：整体进度按各数据集估算字节**加权折算**（抓图斑矢量→属性模版→
     字典→…→影像→打 zip 各阶段连续推进），进度值来自后台任务
     `progress_updated(int)`；任务开始前置 0，全部成功（含打 zip）置 100，
     失败/取消复位 0 并给明确提示——对齐 buffer 弹窗“开始置 0、完成置 100”
     的行为约定；
   - **不要照搬 buffer 的坑**：buffer.py 注释记录过 processing 原生
     `feedback.progressChanged` 直连控件槽会原生崩溃；离线下载进度改走
     任务自身 `QObject.pyqtSignal`（后台线程 emit、主线程 `setValue`），
     不依赖 processing feedback，无此崩溃风险。
   - 下载开始后进度条进入活跃态（可再叠加一个“下载中…”的当前阶段文本），
     「开始下载」禁用，避免重复提交。
6. **下载管理**：打开下载任务列表（状态/进度/暂停恢复/取消/重试/打开目录）。
   可与弹窗并存；下载进行中弹窗不关闭（展示本条进度条），也可由用户切到
   下载管理看整体。
7. **取消**：下载进行中点击 = 停止本次下载（保留已完成 staging，供重试/续传）；
   未开始时点击即关闭弹窗。已提交到下载管理的任务由其面板接管，互不冲突。
8. **开始下载**：校验 → 生成下载请求 → 提交 `OfflineDownloadService` →
   后台线程执行 → 弹窗内进度条实时更新 → 完成打 zip。

## 5. 空间范围语义与裁剪

### 5.1 三种范围的几何来源

| 范围 | 来源 | 投影 |
|---|---|---|
| 全部空间范围 | 任务字段 `task_extent`（任务 JSON 下发的空间范围；不依赖图斑是否已画） | 转目标数据源 CRS |
| 视图范围 | `QgsMapCanvas.mapSettings().extent()`（主界面回调注入） | 同上 |
| 框选范围 | 画布框选矩形（交互工具返回） | 同上 |

> 默认“全部空间范围”的语义 = **任务字段定义的范围**（任务 JSON 配置里的空间
> 范围字段），是下载范围的上界：任务下发的矢量/影像都在其内或与其相交。图斑矢量
> 本身可能为空（未画），所以**不能用图斑外包当范围**。抓取各数据集时把数据源
> 范围与任务范围取交（见 5.2）；任务未带该字段 → 提示改用视图/框选（见 §4 要点 2 兜底）。

### 5.2 裁剪策略

- **矢量**：FeatureServer 抓取时在 `query` 加 `geometry=<envelope>&geometryType=
  esriGeometryEnvelope`（或对图层做范围子集），服务端只回交差要素；
- **影像**：按所选范围在**默认层级范围**内抓**瓦片金字塔**（每张瓦片请求带
  范围/层级参数，见 6.2/6.4）——不默认拼整幅 tif；瓦片文件夹 QGIS 可直接按
  本地 XYZ 加载，粒度即缓存粒度、断点续传与打包都更简单。
- **边界处理**：数据源本身范围与所选范围取交；无交时跳过并记日志，避免下载空文件。

## 6. 数据抓取与打包方案

### 6.1 落盘规范（zip 内结构）

```
<taskId>_<taskName>_YYYYMMDD_HHmmss.zip
├── manifest.json                     # 下载清单（每数据集：来源/类型/时相/范围/大小/SHA256）
├── 矢量.gdb/                         # FileGDB（一个 gdb 收纳全部矢量）
│   ├── 图斑                         # feature class：图斑矢量
│   ├── 政区边界
│   └── 参考矢量
├── 影像/
│   ├── 前时相/2024-06-12/tiles/{z}/{x}/{y}.png   # 每条影像/时相一个瓦片金字塔目录
│   ├── 后时相/2024-12-20/tiles/{z}/{x}/{y}.png
│   ├── 本底数据/
│   └── 参考影像/
├── 文件/
│   ├── 属性模版/…
│   ├── 规则包/…
│   └── 字典/…
└── 样式/                             # 可选：图层 .qml 样式，保证离线打开外观一致
```

**manifest.json 结构（契约草案，实现时冻结 schema=1）**

```json
{
  "schema": 1,
  "task_id": "T20260905001",
  "task_name": "某某核查任务",
  "created_at": "2026-09-05T10:30:00+08:00",
  "vector_container": "矢量.gdb",
  "spatial_scope": { "type": "all", "extent_wgs84": [106.0, 28.0, 107.0, 29.0] },
  "datasets": [
    { "kind": "vector", "feature_class": "图斑", "source_type": "arcgis-feature",
      "service_url": "…", "crs": "EPSG:4490", "extent": […],
      "feature_count": 1234, "size_bytes": 12582912, "sha256": "…" },
    { "kind": "imagery", "dir": "影像/前时相/2024-06-12/tiles",
      "zmin": 0, "zmax": 18, "format": "png", "crs": "EPSG:3857",
      "service_url": "…", "tile_count": 4087, "size_bytes": …, "sha256": "…" },
    { "kind": "files", "dir": "文件/属性模版", "entries": [
        { "name": "xxx.tpl", "size_bytes": …, "sha256": "…" } ] }
  ],
  "name_map": { "图斑": "tuban" }
}
```

> `name_map`：gdb/文件名规范化为 ASCII 后还原中文显示名的映射（见 §11）；
> `spatial_scope` 记录所选范围类型与实际外包（WGS84）：`type=all` 时取自任务
> 字段 `task_extent`，`view/box` 记录画布/框选外包——统一归 WGS84 供导入/回传比对；
> 每数据集记 `size_bytes` + `sha256`（瓦片目录按“分块清单”记录或对目录内
> 文件逐条），下载管理/回传据此去重。

关键决策与依据：

1. **“矢量放到 gdb” = FileGDB**：本项目是 QGIS 二次开发，运行时自带 GDAL
   FileGDB **写驱动**，直接 `ogr.GetDriverByName("FileGDB")` 建一个
   `矢量.gdb` 收纳全部矢量 feature class（图斑/政区/参考矢量）。目录型 .gdb
   可整体进 zip、可被 ArcGIS/QGIS 双端读取，无需其它容器与回退。
2. **影像“分别建好文件夹” = 每条影像/每条时相一个独立瓦片金字塔目录**
   `影像/<数据集>/<时相>/tiles/{z}/{x}/{y}.png`（层级范围等见 6.4），避免不同
   数据集/时相混放与同名覆盖；金字塔目录即 QGIS 可直接加载的形态（见 6.4）。
3. **抓取过程 = 分步写盘，最后压缩**：
   先写入 **staging 目录**（`paths.tmp/offline_download/<任务>/…`，结构即 zip
   内结构），全部成功后 `shutil.make_archive` 打 zip 到下载目录，删除 staging。
   这样断网/取消不会留下半个 zip，也方便「下载管理」看分步进度与续传。
4. **manifest.json** 记录元信息，供导入器还原（见 9）与回传比对。

### 6.2 按来源类型的技术路线

运行时先把每个 `DataSource` 归一为 `source_type`（显式优先，否则按 URL 推断）：

| source_type | 代表数据集 | 抓取方式 |
|---|---|---|
| `arcgis-feature` | 图斑/政区/参考矢量 | FeatureServer `query` **分页拉全量**（`resultOffset/resultRecordCount`，尊重 `maxRecordCount`），按所选范围 `geometry` 过滤；直接写 FileGDB（OGR 建 gdb + 逐要素写；属性带编码/中文保留） |
| `arcgis-image` | 前后景/本底/参考影像 | ImageServer 抓**瓦片金字塔**（默认层级范围）：服务带 `tileInfo` 走 `/tile/{level}/{row}/{col}`；仅 `exportimage` 的服务按范围网格循环分块导出（每次请求即一张瓦片），默认不拼整幅。`estimateExportSize`/元数据仅用于容量估算（见 7.2） |
| `wms` / `wmts` | 影像类（服务地址是 OGC） | WMTS 按 tileMatrix 抓瓦片；WMS 按范围网格 `GetMap` 分块出瓦片 → 统一落成 `{z}/{x}/{y}` 金字塔目录；按服务默认出图/层级范围（复用/仿照仓库现有影像瓦片下载管线） |
| `file` | 属性模版/规则包/字典/直链文件 | HTTP(S) 流式下载原文件（`urllib`/`QgsNetworkAccessManager` 分块写），支持断点续传（见 8） |

> 认证：图斑服务多带 token/会话。请求统一走现有网络栈与凭证体系
> （`app/core/auth`），URL 附加/请求头注入 token，抓取器签名预留
> `request_kwargs/headers`。

### 6.3 样式与一致性（离线可用性关键）

矢量：样式、标注配置存 `样式/<图层>.qml`（离线打开时 QGIS 加载 gdb 图层后套
qml，保证与在线一致的渲染与字段字典）。此部分属阶段四导入器内容，打包阶段先
预留目录。

### 6.4 影像下载形态：瓦片金字塔，QGIS 本地直接加载

1. 每个影像数据源（前后景时相/本底/参考影像）按所选空间范围下载
   `影像/<数据集>/<时相>/tiles/{z}/{x}/{y}.png` 瓦片金字塔；层级范围取
   **默认层级范围**：优先服务 `tileInfo` 的 LOD 起止，否则用配置默认
   （建议 z 0–18，可按任务/精度需要收敛 zmax），manifest 记录实际 zmin/zmax。
2. **QGIS 支持直接加载瓦片文件夹**——不需要起 HTTP 服务，用本地 XYZ 连接串
   即可（与在线瓦片同 provider）：
   `type=xyz&url=file:///<解压目录>/影像/<数据集>/<时相>/tiles/{z}/{x}/{y}.png&zmin=..&zmax=..&format=PNG`
   本仓库 `basemap.build_xyz_uri`（app/core/domain/basemap.py）的连接串生成逻辑
   直接复用。
3. 前提与约束：
   - 瓦片文件名/目录必须是 **XYZ 方向** `{z}/{x}/{y}`；若源给的是 TMS 行号需
     换算（`xyz_y = 2^z - 1 - tms_y`，仓库 `imagery_mbtiles/task.py` 有先例）；
   - 层级 zmin/zmax 要在连接串声明，QGIS 才能完整显示该金字塔；
   - 抓取只保留与所选范围相交的瓦片；超出所选空间范围的层级不下载。
4. 个别任务若确实需要“单幅栅格”做叠置分析（如按范围导出整幅影像、需唯一
   文件路径时），可后续追加“整幅导出”选项（ImageServer exportimage / WMS
   bbox），非默认下载形态，与金字塔并存不冲突。

### 6.6 线程、事件循环与 Qt 红线（实现必须遵守）

以下结论来自仓库历史原生崩溃记录与探针验证（见 `.claude/archive` 中影像切片/
缓冲/编辑系列），不是猜测：

1. **顶层模块不 import qgis.core / Qt**（QGIS 运行时装配前不加载，仓库硬性规范）；
   qgis 依赖一律方法内按需 import 或 `TYPE_CHECKING`。
2. **后台任务 = QObject（存活在主线程）+ `daemon threading.Thread` 跑 worker**；
   **禁止把离线下载放进 `QgsTask`/`QgsApplication.taskManager()`**——凡内部走
   `QgsMapRendererParallelJob/SequentialJob` 渲染的原生算法在 QgsTask 工作线程里
   运行会 exit 127 原生崩溃。离线抓取本身是纯 REST 请求（不走 processing/渲染），
   普通线程天然安全。
3. **worker 线程信号先 queued 到主线程普通 Python 方法，再更新 QWidget**；绝不
   跨线程直接操作控件，否则 `0xC0000409`。`progress_updated/stage_changed/
   log_message/taskCompleted/taskTerminated` 只负责 emit，`setValue/append` 都在
   对话框主线程槽里做。
4. **长任务不得留在 Qt 信号回调栈里同步跑**；需同步段（如判空/建目录）用
   `QTimer.singleShot(0, …)` 挪出事件栈（buffer 同款修法），下载本身一律 `start()`
   起线程后立即返回。
5. **先连信号再 `start()`**：快速任务可能立刻完成，错过连接就丢完成事件。
6. **不得把 processing `feedback.progressChanged` 直连进度条控件槽**（实测原生
   崩溃）；离线下载进度走自家 QObject 信号，与 processing 无关。
7. headless/单测环境用到 processing 前先 `Processing.initialize()`（真实 app 已
   自动加载）。QGIS 4.2 为 PyQt6 扁平枚举（`QgsMapLayer.RasterLayer` 等），写
   代码以仓库既有调用为准，不臆造嵌套命名空间 API。

## 7. 磁盘容量估算与空间校验

### 7.1 目标盘剩余空间

选好「下载位置」目录后即算（并把估算写在 UI 上）：

```python
import shutil
free = shutil.disk_usage(target_dir).free   # bytes
```

### 7.2 各数据集估算（估算即算即显示）

| 类型 | 估算方法 |
|---|---|
| 矢量（FeatureServer） | `query?returnCountOnly=true` 拿总数；再发一页（`resultRecordCount=maxRecordCount`）量该页实际返回字节 → `每要素均值 × count`；字段按 UTF-8 放大、geometry 按页字节/要素外推 |
| 影像（arcgis-image / wms / wmts 瓦片金字塔） | 按所选范围 + 默认层级范围，复用 `estimate_tile_count` 同套 lon/lat→tile 公式数**瓦片总数** → `瓦片数 × 平均瓦片字节`（PNG 默认 ~200KB，下载时可先取首瓦片实测字节校准回写 UI）；ImageServer 有 `estimateExportSize` 时用之交叉校验 |
| file 直链 | HTTP `HEAD`/`Range: bytes=0-0` 取 `Content-Length`（失败则保守标记“未知/需下载后确定”） |
| 未决/服务异常 | 记“无法估算”，不计入预检（UI 明确提示该项大小未知），下载中按实际写盘字节累计 |

> 影像服务 tiling 若为非 Web Mercator（本地投影 ImageServer / 自定义 WMTS
> TileMatrixSet），瓦片数按**服务真实切片方案**算（读 `tileInfo` 的 origin/LOD/
> tile size 或 WMTS capabilities），不套 Web Mercator 公式——见 §11 风险表。

估算合计后 **× 冗余系数（建议 1.3）**，得到 `估计总大小`；显示格式 `xx GB/MB`。

### 7.3 预检（开始下载前）

```
可用 = 剩余空间
需要 = Σ已选估算 × 1.3
需要 > 可用  → 阻止并提示：至少还需 X GB，请更换下载位置或减少图层
需要 <= 可用 → 放行；下载中仍每步写盘前查一次剩余空间，不足即暂停并告警
```

## 8. 下载执行与下载管理

### 8.1 领域包结构与职责

请求/范围模型契约（实现草案，放 `model.py`）：

```python
class SpatialScope(Enum):
    ALL  = "all"    # 全部空间范围（默认）= 任务字段 task_extent，与是否画图斑无关
    VIEW = "view"   # 当前视图范围
    BOX  = "box"    # 画布框选范围

@dataclass(frozen=True)
class DownloadRequest:
    """一次离线下载的完整输入（对应弹窗一次「开始下载」）。"""
    task: TaskInfo
    scope: SpatialScope = SpatialScope.ALL
    #: (xmin, ymin, xmax, ymax, authid)；VIEW/BOX 必须带；ALL 由 planner 取
    #: task.task_extent 填充（task_extent 为空 → 校验失败并提示改用视图/框选）
    scope_extent: Optional[tuple] = None
    #: 勾选的数据集键（features 恒含；其余见 §2 数据集清单）
    include: frozenset[str] = frozenset({
        "features", "attr_template", "rule_package", "dictionaries",
        "imageries", "basemap_data", "admin_boundary", "reference"})
    target_dir: str = ""                    # 下载位置（zip 落地目录）
    target_name: Optional[str] = None       # zip 名，缺省按任务+时间自动生成
    zoom_range: tuple[int, int] = (0, 18)   # 影像默认层级范围（可被服务 tileInfo 覆盖）
```

`planner.build_plan(req) -> FetchPlan`：把请求展开成有序抓取清单 `FetchItem[]`
（每项：数据集引用 + source_type + 目标落点 + 估算字节 + 进度权重），并校验
必选图斑存在、范围/磁盘预检（§7.3）。各 FetchItem 的顺序决定进度条推进顺序
（矢量 gdb → 文件 → 影像 → zip）。

```
app/core/domain/offline_download/
├── __init__.py        # 包说明 + 顶层导出（仿 imagery_mbtiles 的按需 import）
├── task_info.py       # TaskInfo / DataSource / ImageryItem（§3）
├── model.py           # SpatialScope/图层勾选枚举、DownloadRequest（任务+范围+所选图层+目标目录）
├── planner.py         # build_plan()：展开每个所选数据集→抓取清单（含估算大小）
├── layout.py          # zip 目录布局常量 + 由计划生成 staging 目录树 + FileGDB 容器管理
├── fetcher.py         # 按 source_type 抓取单一数据集（分页/export/瓦片/文件），report 进度
├── task.py            # OfflineDownloadTask(QObject)：后台线程跑整个计划，pyqtSignal 汇报
├── service.py         # OfflineDownloadService 门面：submit(请求)/cancel/状态查询
├── manager.py         # DownloadManager：下载任务注册表 + 持久化（恢复断点）→「下载管理」
└── disk.py            # shutil.disk_usage 封装 + 估算汇总/预检（§7）
```

分层与信号面**对齐现有约定**：

- 顶层模块不 import qgis.core（QGIS 运行时装配前不加载，见仓库规范）；
  需要时在方法内按需 import / `TYPE_CHECKING`；
- 后台执行沿用**普通 `threading.Thread` + `QObject.pyqtSignal`** 模式（参考
  `imagery_mbtiles/task.py`——QgsTask 后台渲染会原生崩溃的坑）；信号面：
  `progress_updated(int)`、`stage_changed(str)`（当前抓哪个数据集）、
  `log_message(level,msg)`、`taskCompleted`、`taskTerminated`、`exception`；
  红线清单见 §6.6。
- **纯逻辑与 qgis 依赖分层**：`task_info/model/planner/layout/disk` 里不触碰
  qgis/Qt 的部分保持纯 Python（与 `flow/types` 同约定），可在无 QGIS 环境下
  headless 单测；真正构造图层/网络请求的函数集中在 `fetcher/task` 内按需 import。
- 下载过程尽量复用项目现有网络/凭证/坐标设施（清单见 §6.5），不另造轮子。

### 8.2 执行编排（一个任务 = 一个计划）

```
校验磁盘空间 → 建 staging → manifest 骨架 →
  [抓图斑矢量 → 写 gdb]        // 必选
  [抓属性模版/规则包/字典 → 文件目录]
  [可选图层按勾选逐个抓]        // 每个数据集：查元数据→估算→抓→写盘→校验
打 zip（staging → 目标目录）→ 删 staging → 更新 manifest（大小/校验和）
→ taskCompleted
```

任一步失败：
- 可续传项（直链文件/瓦片）断点续传（写 `.part` 临时文件 + `Range` 头）；
- 可重试项自动重试 N 次（指数退避），仍失败记日志并把该数据集标失败；
- 整体状态 `FAILED_PARTIAL`：已完成数据集保留，用户可重试失败项（不做半 zip）。

### 8.3 下载管理（“下载管理”按钮）

列表字段：任务名 / 状态（待下载·下载中·暂停·成功·部分失败·失败·已取消）/
进度 / 大小 / 时间 / 操作（暂停·继续·取消·重试·打开所在目录）。

- 重启应用后恢复：manager 把任务状态写到 `paths.tmp` 下 JSON（含 staging 进度），
  启动时扫描，允许继续/重试；
- 文件类断点续传与矢量分页继续均依赖 staging + manifest 增量，避免重复拉全量。

## 9. “支持离线使用”整体处理方案

“支持离线下载”不只把文件搬下来，还要保证**离线可打开、可作业、可回传**：

1. **下载物自描述**：zip 内 manifest.json 记录每个数据集的来源/范围/CRS/校验和，
   导入器据此还原图层，不依赖网络。
2. **离线工程导入（阶段四）**：解压到用户工作目录 → 读 `矢量.gdb` 建矢量层；
   影像按 6.4 的本地 XYZ 连接串直接加载各 `影像/**/tiles/` 金字塔建栅格层；
   套 `样式/*.qml`；生成/更新本地工程文件（QGIS `.qgs`）与工程视图，底图缺失
   时提示可切本地底图。
3. **离线作业**：与在线模式共用同一套编辑/质检/绘图领域服务（图层是本地 gdb 层，
   编辑写本地文件），核查结果写本地；成果数据与问题列表导出到
   `成果/` 目录。
4. **回传（后续）**：断网回到有网后，从 manifest + 成果目录比对，把新增/修改的
   图斑成果、照片、质检结论按服务接口增量上传（校验和去重）。此为独立子方案。
5. **网络栈细节**：请求带超时/重试、代理支持、凭证按现有 auth 体系；
   所有抓取先探活（GetCapabilities / `?f=json`），失败给明确中文错误并允许重试。

## 11. 风险与未决事项

| 事项 | 影响 | 对策 |
|---|---|---|
| 任务 JSON 未提供 `task_extent` 且未画图斑 | “全部空间范围”为空，无从裁剪 | 预检拦截并提示改用视图/框选；范围字段以任务配置为准，不拿图斑外包当兜底 |
| FeatureServer 字段含二进制/大数据块 | 估算与写入失真 | 抓取白名单/字段统计，过大字段单独转存文件目录 |
| 前后景地址形态未定（双地址 vs 多时相列表） | TaskInfo 解析 | 用 `ImageryItem[]` + phase 自适应承载两种形态 |
| 影像服务无 estimateExportSize | 大小未知/估算粗 | 记为“未知”不纳入预检，UI 明确提示 |
| 认证 token 过期 | 抓取中途失败 | 抓取器收到 401/403 自动重取凭证并续传 |
| 大任务 staging 磁盘占用 | 中途磁盘满 | 分步写盘前查剩余空间；打包采用边写边 zip（流式）降占用 |
