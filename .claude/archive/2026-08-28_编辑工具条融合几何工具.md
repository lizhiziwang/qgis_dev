# 2026-08-28 编辑工具条融合几何工具

## 需求
- 在**编辑工具条**（`DigitizingToolbar`，`draw_toolbar.py`，编辑 Tab）新增「融合几何」工具：
  右键单击要素 → 加入待融合集合（红色高亮框标出）；再次右键同一要素取消；
  左键双击 → 把所有已选要素融合为一个。
- 融合后的几何要**尽可能与原图形形状一致**（保留顶点精度、不做简化）。

> 注：用户 @ 了 `tool_bar.py`（通用工具条），但需求描述的交互是**编辑操作**
> （改要素几何/删要素），且要求编辑态；实现放在编辑工具条 `draw_toolbar.py`
> （「编辑工具」QToolBar）更贴合语义。若需移到通用工具条，把按钮 + `enable_merge_tool`
> 平移过去、编辑态判断改为自管理即可。

## 改动
- 新增 `app/ui/tools/merge_geometry.py`（~8KB）：`MergeGeometryTool(QgsMapTool)`
  - 右键：10px 容差矩形 + 复用 `app.core.domain.check.query.intersect_features`
    （空间索引 + 精确相交，自动处理画布 CRS ≠ 图层 CRS）；多要素命中取最上层；
    fid 加入/移出 `_fids`（保持选中顺序，首个 = 融合后保留属性的要素）
  - 双击：`QgsGeometry.unaryUnion(geoms)` 求并，再按结果形态分派：
    - 结果**单部件**（相邻/重叠）→ 直接使用：合并公共边、重叠求并、**全部原始
      顶点保留**、不做简化
    - 结果**多部件**（角对角 / 微缝隙 / 完全分离）→ `_merge_multipart_to_single`
      按部件间距**分级**处理：
      - 间距 ≤ 包围盒短边 × 5%（角对角 / 微缝隙等矢量化误差）→ **微膨胀缝合**
        `buffer(+w).buffer(-w)`，w = 间距×0.6 + 短边×0.005：只在缝隙处补窄带，
        面积几乎不变（实测 extra≈0.001~0.2、missing≈0）
      - 间距大（**真分离**）→ **多边形凹包** `QgsGeometry.concaveHullOfPolygons
        (multi, 0.3, False)`（**参照 JTS ConcaveHull 的 GEOS 移植**）：输入
        多边形边界保持不变、只用凹包填充部件间间隙，实测各场景均不丢面积；
        参数 0~1 越小越贴合点集（半环 extra 12 vs 25、三块 39 vs 57）
      - 兜底 `convexHull`（理论不可达，凹包失败时）
    - 并集失败兜底 `QgsGeometry.collectGeometry`（形状 100% 保留）
    - **坑 1：凹包（`QgsGeometry.concaveHull`）不可用**——percentPoints 语义是
      0~1 小数，0.3 意味着“只保留 30% Delaunay 三角形”，实测**确定性丢失原
      面积**：错位微缝隙场景丢 99/198.8（剩一半）、L 形丢 50/130、三块丢
      18/108；0.4~0.6 仍丢（微缝隙丢 99），0.8~0.9 才不丢但已≈凸包；顶点少
      时行为不连续 → 判定不可靠，弃用
    - **坑 2：shapely.concave_hull（GEOS 3.14 = JTS ConcaveHull 原版移植）也
      丢面积**——GEOS 凹包只保证包含输入**点**、不保证包含输入**多边形面积**：
      错位微缝隙丢 99、L 形丢 50、三块 ratio≤0.3 丢 18；而
      `concaveHullOfPolygons` 是多边形专用（边界保持 + 间隙填充），实测全场景
      missing=0 → 选它
  - 编辑缓冲写入：`beginEditCommand("融合几何")` + `changeGeometry(keep_fid, merged)`
    + `deleteFeatures(其余)` + `endEditCommand()` → **一个撤销步骤**；异常路径
    `cancelEditCommand()`
  - 结果 `layer.select([keep_fid])` 高亮 + `QTimer.singleShot(0, ...)` 延迟
    `canvas.refresh()`（仓库约束：不在 Qt 事件栈内 refresh）
  - 橡皮筋按图层几何类型建点/线/面 band；`_current_layer()` 锁定图层，
    切换图层自动清空集合（防跨层 fid 误删）
  - Esc → 延迟 `unsetMapTool` 退出；`deactivate()` 清 band
  - hint 回调把状态提示推给 `main_window.messageBar`
  - **空间索引缓存失效**：融合删除要素后清 `clear_spatial_index(layer)`
    （`build_spatial_index` 缓存挂在 layer 属性上，含已删 fid 会导致后续
    命中已删要素）；`_hit_fid` 再过滤一遍无效 fid 双保险
  - **QgsGeometry 所有权坑**：`QgsGeometry(geom.constGet().geometryN(i))` 会
    转移部件所有权导致 double-free 段错误 → 部件遍历一律
    `QgsGeometry.fromWkt(part.asWkt())` 深拷贝；单部件时 `constGet()` 返回
    QgsPolygon（无 numGeometries）→ 先判 `isMultipart()`
- 修改 `app/ui/main_window/draw_toolbar.py`：
  - 「融合几何」按钮（文本按钮）加在 保存编辑 之后、分隔符之前
  - `_set_edit_actions_enabled`：融合几何**仅在编辑态可用**（`editing_now=True`）
  - `enable_merge_tool()`：无矢量图层/未编辑 → 警告；清掉既有绘制/融合工具后
    `setMapTool(MergeGeometryTool)` + `QMessageBox.information` 提示操作方式
  - `clear_draw_tool()`：同时清理 `merge_tool`
  - docstring 更新为 7 个按钮
- 新增 `tests/ui/main_window/test_merge_geometry.py`（14 项，canvas/tool 均 `deleteLater` 清理）

## 关键设计 / 坑
- **按钮定义顺序**：`_set_edit_actions_enabled(False)` 在 `_build_toolbar` 中先于
  按钮创建调用 → merge 按钮必须先定义再整体禁用，否则 AttributeError。
- **QGIS 4.2 API 实证**：
  - `QgsGeometry.unaryUnion([g1, g2])` 可用，保形（相邻面并集外环 7 点，公共边
    移除、无简化）；`QgsGeometry.collectGeometry` 兜底可用
  - `QgsVectorLayer.changeGeometry(fid, geom)` / `deleteFeatures(fids)` 在编辑
    缓冲内可用，`beginEditCommand` 包成一个撤销命令（undo→3 要素、redo→1）
  - `QgsGeometry.numPoints` 已移除（4.x），改用 `sum(1 for _ in g.vertices())`
  - `selectedFeatureIds()` 返回 **list**（非 set）
  - `QgsMapToPixel.toMapCoordinates` 不收 QPointF（真实 Qt 事件是整数 QPoint）→
    工具内做 QPointF→QPoint 防御转换
  - `QgsMapCanvas` 无 `updateMapSettings()`；裸画布坐标变换需
    `show()` + `processEvents()` 触发渲染后才可用
- **编辑态强约束**：未 `startEditing` 时双击只提示不修改数据（防误改）
- **测试工程对象泄漏 → 全量段错误**：13 个用例各建独立 `QgsProject()` 但未清理，
  全量跑时 GC 析构触发 C++ 堆损坏（0xc0000374 / exit 139），在
  test_tool_bar_highlight 处确定性截断（单独跑 main_window 套件不崩，难排查）；
  修复：仿 test_qmap_compare.py 的 `project` fixture —— teardown 时
  `layerTreeRoot().removeAllChildren()` + 逐个 `removeMapLayer` +
  `processEvents()` ×2（让 deleteLater 的画布真正销毁）+ `sip.delete(p)`
- 融合后工具保持激活，可连续融合多组；每次融合后集合清空
