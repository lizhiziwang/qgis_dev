# 状态栏投影选择器显示"无效投影"——构造后未绑工程 CRS

> 2026-08-18。用户："`@app/ui/main_window/status_bar.py` 中的
> `QgsProjectionSelectionWidget` 在应用中为什么显示无效投影"。

## 根因

`QgsProjectionSelectionWidget.__init__(parent)` 构造完后，`crs()` 默认是一个
**空**的 `QgsCoordinateReferenceSystem()`（`isValid() == False`、`authid()` 空）。
本组件状态栏构建顺序里：

1. `setOptionVisible(ProjectCrs, False)` —— 把"工程当前 CRS"这个快速选项**隐藏**；
2. 没别处调用 `setCrs(...)` 把当前工程 CRS 灌进去。

结果：控件拿不到 CRS，又被屏蔽了 ProjectCrs 兜底选项 → 永久停留在"无效投影"
显示态。用户视觉上看到的就是字面"无效投影"。

探针 `_probe_proj_sel.py`（已删）实测：

```
构造后:
  crs().isValid() = False
  crs().authid()  = <empty>
```

## 修复（`app/ui/main_window/status_bar.py`）

- 构造后立刻 `proj_selector.setCrs(project.crs())`：把当前工程 CRS 灌进去；
- 连接 `project.crsChanged` 信号，**用户改工程 CRS 或打开工程后**控件自动同步；
- `crsChanged` 是无参信号、`setCrs` 需要 CRS 参数 → 包 `_sync_proj_selector()`
  lambda；该闭包在主窗口关闭后单例 `QgsProject` 仍可能发信号，那时
  `proj_selector` 已被 sip 析构，访问会抛 `RuntimeError: wrapped C/C++ object
  of type ... has been deleted` → 内层再 `try/except RuntimeError: pass`
  兜底（Qt 槽内未捕获会 native 崩溃，与仓库记忆一致）。

## 测试

`tests/ui/main_window/test_status_bar.py` 新增 `test_projection_selector_displays_current_project_crs`：

- 在真实 `MainWindow` 上 `findChild(QgsProjectionSelectionWidget)` 拿到控件；
- 修复前会失败 `crs().isValid() == False`；修复后等于当前工程 `EPSG:4490`；
- 修复后 `authid() == "EPSG:4490"`。

**20/20 通过**，`ruff --select F,E9,I` 干净。
