# 操作日志：模式切换 / 算法工具 / 图层导入导出

## Context（为什么改）

用户要求：「店家切换模式首先要记录日志，进行算法工具也要记录日志。图层的
导入导出也要记录日志」（即**切换任务/工程模式、运行算法工具、导入/导出图层**
三类操作都要写进应用日志，供日志面板追溯操作历史）。

此前只有服务层自带的错误日志（`logger.error` 失败分支），缺少**成功执行**的
可追溯记录；模式切换、图层导入/导出入口完全没有日志。

## 方案

沿用仓库既有服务日志惯例：模块级 `logger = get_logger(__name__)` +
`logger.info(...)`。统一两种日志句式：

- **开始**：`执行算法 {algo}：输出={target}`（含输出路径 / 目标坐标系 / 起点终点
  等关键参数）
- **完成**：`{algo} 完成 → {结果}（{n} 要素…）`（含结果图层名 / 要素数 / 文件路径）

### 1. 模式切换（main_window.py）

`_build_chrome` 里 `self.title_bar.mode_changed.connect(self._on_mode_changed)`；
新方法把模式 key 映射成中文再记日志：

```python
def _on_mode_changed(self, mode: str) -> None:
    from app.ui.main_window.title_bar import MODE_PROJECT, MODE_TASK
    label = {MODE_PROJECT: "工程模式", MODE_TASK: "任务模式"}.get(mode, mode)
    logger.info("模式切换：%s", label)
```

### 2. 图层导入 / 导出（main_window.py）

- **导入统一漏斗** `_add_layer_to_project`（打开文件 / 浏览器双击 / 拖拽都走这里）
  末尾：`logger.info("导入图层：%s（来源=%s）", layer.name(), src)`，
  `src = getattr(layer, "path_c", None) or layer.source()`
- **导出** `_export_layer`：`result = dlg.exec()` 后若
  `result == QDialog.DialogCode.Accepted`，
  `logger.info("导出图层：%s → %s", layer.name(), dlg.fileName() or "")`
  （`QgsVectorLayerSaveAsDialog.fileName()` 在 exec 返回后可用）
- 顺带补了同漏斗下的两个成功日志：`_on_browser_create_vector`
  （`新建矢量文件：%s（驱动=%s）`）和 `_on_browser_add_gdb_layer`
  （`GDB 新增图层：%s → %s`）

### 3. 算法工具执行（core/domain）

全部 processing 算法入口补「开始 + 完成」两段日志：

| 文件 | 算法 | 开始日志要点 |
|---|---|---|
| buffer/service.py | native:buffer | 输出 / 距离 / 融合 |
| reproject/service.py | native:reprojectlayer | 输出 / 目标 CRS |
| oriented_bbox/service.py | native:orientedminimumboundingbox | 输出（原无 logger，已加） |
| shortestpath/service.py | native:shortestpathpointtopoint | 输出 / 起点 WKT / 终点 WKT / strategy |
| overlay/service.py | native:intersection/union/difference/symmetricaldifference | 按运算逐个记，带异常分支 |
| generic_alg/service.py | 任意 gdal:/native:（59 个） | 输出 + 新 helper `_describe_output` |
| tiles/task.py | native:writevectortiles_xyz | 输出目录 / 缩放范围（QgsTask 后台线程，原无 logger） |

已在记日志、无需改的：imagery_tiles/task.py 与 imagery_mbtiles/task.py
（`_log_line` 已写「开始影像切片 / 参数 / 输出目录 / 切片完成」并转发
`logger`）；flow 流程执行（flow_editor/log_panel.py 的 `LogDock.log` 已把节点
起止/成败写进 app 日志）。

### 4. 回归测试

- 新增 `tests/ui/main_window/test_logging.py`（3 测试）：模式切换 / 导入 / 导出
  日志断言
- `tests/core/domain/buffer/test_service.py` 追加
  `test_buffer_logs_algorithm_execution`：断言「执行算法 native:buffer」+
  「native:buffer 完成」两段日志

**关键坑**：不能用 `caplog`。`tests/conftest.py` 的 `_isolate_logger` autouse
fixture 每个测试前 `_RootSink.reset()`，代码首次 `get_logger` 又触发
`_RootSink.configure` **清空 root 上所有 handler**（含 caplog 挂的那个）。
改用「先 `get_logger()` 触发 configure，再挂临时 list handler」捕获消息。

顺带修复 `test_output_path_writes_gpkg` 顺序依赖：它从未调
`Processing.initialize()`，单独跑（或排在最前）时报
`QgsNotSupportedException: Processing plugin has not been loaded`。补显式初始化。

## 风险与限制

- **`_describe_output`**（generic_alg）：结果值可能是图层对象 / 路径字符串 /
  标量，helper 统一转成 `输出名=值` 日志串；值缺失显示 `(空)`
- **tiles/task.py 后台线程**：`logger.info` 在 QgsTask 线程调用，Python logging
  线程安全，直接写文件无锁问题
- **测试断言只查「含关键子串」**：日志里含中文 + 动态参数，用子串匹配而非
  精确断言，降低脆弱性
