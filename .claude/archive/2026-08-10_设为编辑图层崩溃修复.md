# 2026-08-10 设为编辑图层按钮崩溃修复（pushMessage level int→枚举）

## 问题

图层右键菜单点「设为编辑图层」→ 进程崩溃（exit 127、无 traceback），与 show() 崩溃同类。

## 根因

PyQt6 不再把 `int` 自动转成 QGIS 枚举。`main_window.py:1123` 的：

```python
self.messageBar.pushMessage(..., level=0, duration=3)
```

`level` 参数是 `Qgis.MessageLevel` 枚举；PyQt5 下 `level=0` 自动转，PyQt6 拒绝 → `TypeError: argument 'level' has unexpected type 'int'` → 槽内未捕获 → 原生崩溃。直接调用方法（非槽）能拿到 traceback 定位。

## 修复

`app/ui/main_window/main_window.py`：
- `from qgis.core import Qgis`（补导入）
- 11 处 `level=0` → `Qgis.MessageLevel.Info`
- 1 处 `level=2` → `Qgis.MessageLevel.Critical`（旧 int 映射：0=Info/1=Warning/2=Critical/3=Success）

`qgis_bar.py` / `space_query.py` 用的裸 `Qgis.Info`/`Qgis.Warning` 快捷方式在 QGIS 4.2 仍存在（探针确认 `hasattr` 全 True），不用改。另外：`QgsMessageBar` 已从 `qgis.core` 移到 `qgis.gui`（main_window.py 早已从 qgis.gui 导入）。

## 验证

- 直接调用 `_set_edit_layer()`：修复前抛 `TypeError`（有 traceback），修复后 OK。
- `QAction.trigger()` 槽路径：OK，`edit_layer` 正确设为该图层。
- 端到端探针：真实 `context_menu_requested` 信号 → 弹窗内找到「设为编辑图层」action 并 trigger → `edit_layer is layer` 成立 → 无崩溃，EXIT=0。
- 全量测试：157 passed，1 skip（fastapi），EXIT=0。
- 探针已删；`grep 'level=\d' app/` 无残留。
