# 画布左上角缩放工具（CanvasZoomTool）

日期：2026-08-06

## 做了什么

新增一个覆盖在地图画布（QgsMapCanvas）左上角的缩放工具组件，竖向排列：

- **放大按钮**（顶部，`canvas.zoomIn()`，单次立即缩放，不切换当前激活工具）
- **垂直进度条/滑块**（可拖动缩放，对数空间映射，每步约 10.4% 缩放因子）
- **缩小按钮**（底部，`canvas.zoomOut()`）

滑块 ↔ 比例尺映射：`s(p) = MAX_SCALE * (MIN_SCALE/MAX_SCALE)^(p/100)`，范围 1:500（最放大）到 1:1000 万（最缩小），越界钳制。滑块拖动时围绕画布中心缩放。

改动文件：

| 文件 | 改动 |
|---|---|
| `app/ui/common/canvas_zoom.py` | 新增 `CanvasZoomTool(QFrame)` |
| `app/ui/common/styles.py` | 新增 `CANVAS_ZOOM_PANEL_QSS` / `CANVAS_ZOOM_BUTTON_QSS` / `CANVAS_ZOOM_SLIDER_QSS` |
| `app/ui/main_window/main_window.py` | import + `_build_central_widget()` 后实例化 `self.zoom_tool` |

## 关键结论

- **QGIS 3.40 实测**：`QgsMapCanvas.setOverlayWidget` / `setScale` / `resized` 信号均不存在 → 覆盖层用 canvas 子 QWidget + `move(8,8)` + `raise_()`（showEvent 里再置顶兜底），子控件坐标相对父左上角，窗口 resize 自动保持锚定。
- 程序化设缩放只能用 `canvas.zoomScale(scale, canvas.center())`；同步用 `scaleChanged(double)` 信号（纯平移不触发），不用 `extentsChanged()`。
- `_syncing` 布尔守卫包裹 `setValue`（try/finally），防止缩放反馈循环；用 `valueChanged` 而非 `sliderMoved`，保证点槽/键盘也能缩放。
- 缩放按钮走单次立即缩放，与工具栏橡皮筋缩放（QgsMapToolZoom 模式）共存，滑块都会自动同步。

## 验证

- `py_compile` 三个文件通过。
- QGIS 3.40 Python 下独立脚本验证：模块 import 正常；映射往返一致、单调、钳制正确（滑块 0/25/50/75/100 → 1:1000万 / 1:84万 / 1:7.1万 / 1:5900 / 1:500）。
- **待用户手动验证**（需启动应用）：面板显示在左上角、按钮缩放、滑块拖动缩放、外部缩放同步、平移不动滑块、拖到端点钳制不跑飞。

## 追加修复（2026-08-06）：布局塌缩 → 按钮重叠 / 滑块压扁

用户实测发现"样式叠在一起"。离屏对照实验定位根因：

- **根因**：`CanvasZoomTool` 作为 canvas 的**自由悬浮子控件**（不被父布局管理），`show()` 不会自动套用 `sizeHint`，widget 高度塌缩成 30px → 两个 28px 按钮在 30px 里重叠、滑块被压成 3px。
- 对照组证明：纯 QWidget + 手动 `resize(52,160)` 时布局完全正常（滑块正确拉伸 84px）→ 排除 QSS / QFrame / 透明属性因素。
- **修复**：`__init__` 里 `_build_ui()` 之后加 `self.adjustSize()`，显式套用 sizeHint。修复后几何：`btn_in(7,7,38,28)` / `slider(7,39,15,84)` / `btn_out(7,127,38,28)`，tool 52x162，无重叠。
- 同步链路一并验证：点放大 → 假 canvas scale 减半 → 滑块回 `23`（对应 1:50万），`_syncing` 守卫无反馈循环。

> 注意：QGIS 3.40 的 QGIS-Python 环境里 `widget.grab()` / `render()` 在离屏/未 show 状态下拿不到像素（全透明/全绿），样式只能靠几何验证 + 用户在真实应用确认。若之后要自动化 UI 验证，需另想办法。

## 追加修复 2（2026-08-06）：滑块拖动崩溃 + 按钮改符号

用户实测：拖动滑块 → 进程崩溃 `0xC0000409`；并要求按钮改用 `+` / `-` 符号。

**崩溃根因**：`QSlider.valueChanged` 在拖动时高频触发，每个事件都同步调 `canvas.zoomScale()`，在滑块鼠标事件栈内重入触发渲染 → QGIS 原生崩溃。仓库已有同类崩溃的既定解法（`main_window._remove_layer` 用 `QTimer.singleShot(0)` 推迟出事件栈）。

**修复**：改为**固定间隔节流**（40ms 循环计时器）：
- `valueChanged` 只记录 `_pending_scale` + 保证计时器在跑，不直接缩放；
- 计时器在事件栈外每 40ms 应用最新目标值（保持拖动实时性）；
- `sliderReleased` 松手立即应用最终值并停表；
- `_apply_zoom` 里额外守卫 `extent().isEmpty()`，避免空范围 NaN 崩溃。

**按钮改符号**：`"+"` / `"-"`，tooltip 保留"放大（+）"/"缩小（−）"，`CANVAS_ZOOM_BUTTON_QSS` 字号 13→16px 加粗。

**验证**（假 canvas 节流测试）：拖动期零调用；40ms 后计时器合并应用最新值（slider60→26265）；松手立即应用（slider80→3623.9）并停表；pending 清空；`_syncing` 守卫无反馈循环。

## 追加修复 3（2026-08-06）：拖动滑块"没反应"

节流修复后用户实测：拖动滑块无反应（地图不缩放）。

**根因**：一个竞态——拖动期间节流计时器应用缩放 → `scaleChanged` → `_sync_from_canvas` → `setValue()` 把手柄**拉回**已应用位置，和用户拖动手势打架。节流把缩放频率降到 40ms 一次后，这个"回拉"每 40ms 发生一次，视觉上就是滑块被钉在原地、怎么拖都不动（值被反复重置）。

**修复**（`_dragging` 守卫，`app/ui/common/canvas_zoom.py`）：
- 新增 `self._dragging` 标志：`slider.sliderPressed → True`，`sliderReleased → False`；
- `_sync_from_canvas` 顶部 `if self._dragging: return`——拖动期间**不回写**手柄，滑块值由鼠标主导；
- `sliderReleased` 里同时把"应用最终缩放 + 回写对齐"统一推迟到 `QTimer.singleShot(0)`，出鼠标事件栈（与拖动期同步缩放同类的 0xC0000409 重入风险一并规避）。

**验证**（假 canvas 守卫测试）：
- 按下→拖到 50→等 100ms：计时器应用了 50 对应缩放，**手柄仍停在 50**（不被拉回）；
- 拖到 80→等 100ms：应用最新值（≈3623.9）；
- 松手：停表 + 回写对齐（fake-canvas 里"slider aligned: 23"是 FakeSettings.scale 恒返回 1:100万 的测试产物，非 bug）；
- 松手后外部 zoomIn → 正常同步回写（守卫只在拖动期生效）；
- **安全网**：拖到 70 立即松手（<40ms 计时器未到），松手路径仍应用了最终值（→9756），保证任何拖动节奏都有响应；
- `py_compile` 通过。

> 后续若"40ms 节流显得拖动手感滞后"或 `+` / `−` 符号观感需调整，用户反馈后再改。

## 追加修复 4（2026-08-06）：滑块拖动地图仍不缩放 —— 真正的根因

`_dragging` 守卫修复后用户实测：滑块拖动，**地图完全不缩放**。

假 canvas 逻辑测试证明组件"调用了 zoomScale"，但验证不了真实 canvas 的行为。用真实 QGIS 3.40 环境（`QgsApplication` + 真实 `QgsMapCanvas` 离屏）做决定性探测：

**真正的根因**（API 签名误判）：
- `QgsMapCanvas.zoomScale` 本构建签名是 **`zoomScale(scale: float, ignoreScaleLock: bool = False)`**，**根本没有 center 参数**。
- 我们一直调 `zoomScale(scale, canvas.center())` —— 第二参 `QgsPointXY` 不匹配，**每次都抛 `TypeError`**。
- 而 `_apply_zoom` 里是 `except Exception: return` 静默吞掉 → 40ms 一次的全部缩放调用全被吞 → 地图纹丝不动（表现为"拖动没反应"）。
- 单参 `zoomScale(scale)` 完全有效，且**默认以当前画布中心为缩放中心**（实测：center 从 POINT(30,70) 缩放到 1:800 后不变）——正是"围绕中心缩放"的需求。
- 之前"第二参传 center 导致 0xC0000409 崩溃"的推断**不成立**（实为 TypeError，不会重入渲染）；首次崩溃更可能是 `setValue` 反馈循环的栈溢出，已被 `_syncing` 守卫消除。

**修复**（`app/ui/common/canvas_zoom.py`）：
- `_apply_zoom` 改为 `self._canvas.zoomScale(scale)`（单参，center 自动保持）。
- 把 `except Exception: return` 静默吞异常改为 `logger.error(...)`（用仓库标准 `app.infra.logging.get_logger(__name__)`），记到 `logs/app.log`，同类故障不再无痕。

**验证**（真实 QGIS 端到端，假 canvas 全部弃用）：
- 真实 `QgsMapCanvas` + 真实 `CanvasZoomTool`，模拟拖动（sliderPressed → setValue(80) → 等 100ms）→ 画布比例尺从 4071 万变 **3623.9**（滑块 80 的预期值）✅
- 拖动中滑块值保持 80 不被拉回 ✅；画布中心 POINT(50,50) 不变 ✅
- 拖到 100 → 1:500（端点）✅；松手回写同步 100 ✅
- `+`/`-` 按钮缩放正常 ✅
- `py_compile` 通过。
- **待用户真实应用复测**：拖动滑块应实时缩放地图、手柄随手走。
