# 2026-08-10 新增要素绘制完成崩溃修复 + 崩溃日志机制

## 问题

用户：开始编辑 → 新增要素 → 绘制几何完成之后程序崩溃退出（exit 127，无 traceback）。要求：加崩溃日志 + 修复。

## 根因（绘制完成崩溃）

`DigitizingToolbar.finish_draw`（`app/ui/main_window/draw_toolbar.py:287`）在几何完成后构造 `CustomAttrDialog`（`app/ui/dialogs/custom_attr.py`），模块内两处 PyQt6/QGIS 4.2 bug：

1. **`QFrame` 未 import** → `scroll.setFrameShape(QFrame.Shape.NoFrame)` 抛 `NameError`（迁移时丢了导入）。
2. **`QFormLayout.DontWrapRows`** → PyQt6 枚举必须限定，`AttributeError`。

两者都在"绘制完成 → 弹属性窗"的槽路径里未捕获 → native 崩溃（与之前 `.exec_` / `pushMessage(level=0)` 同一类：PyQt6 严格化在槽内未捕获 → exit 127）。探针确认：直接调 `CustomAttrDialog(...)` 先撞 `QFrame` NameError，修复后立刻撞 `QFormLayout.DontWrapRows` AttributeError。

## 修复

`app/ui/dialogs/custom_attr.py`：
- 补 `QFrame` 导入
- `QFormLayout.DontWrapRows` → `QFormLayout.RowWrapPolicy.DontWrapRows`

## 崩溃日志机制

新增 `app/infra/logging/crash.py`（`install()` / `reset()`），三层覆盖：

| 层 | 机制 | 产出 |
|---|---|---|
| 未捕获 Python 异常（含 Qt 槽/C++ 回调） | 重写 `sys.excepthook` | `logs/crash.log`（纯文本） |
| 不可上报异常（`__del__` 等） | 重写 `sys.unraisablehook` | `logs/crash.log` |
| 原生崩溃（access violation / abort / stack overflow） | `faulthandler.enable(file=fd, all_threads=True)` | `logs/crash_faulthandler.log`（fd 写，绕过缓冲） |

- 关键实证：PyQt6 槽内/C++ 回调异常**先调 `sys.excepthook`** 再决定是否 abort → excepthook 就能拿到 traceback，即使进程随后死掉。
- `faulthandler.enable` 已启用时抛 RuntimeError（pytest/PyInstaller 场景）→ `_fh_enabled_by_us` 记录，reset 只 disable 自己启用的。
- 装配：`app/bootstrap/__init__.py` `main()` 在 `_configure_logging` 后、QGIS 初始化前 `install_crash_logging(paths.logs)`；`app/infra/logging/__init__.py` 导出 `install_crash_logging`。
