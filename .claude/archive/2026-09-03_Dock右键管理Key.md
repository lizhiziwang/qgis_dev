# Dock 右键「管理 Key」：按 provider 集中管理底图服务 key（天地图 tk + 高德预留）

日期：2026-09-03

## 背景

承接 Dock 右键菜单演进（[[2026-09-02_通用工具条在线底图Dock]] → [[2026-09-03_在线底图右键添加自定义底图]]）。
用户追加：「右键菜单在添加一个管理 Key 的功能，点击后弹窗管理各个底图的 key。」

改造前痛点：天地图浏览器端 tk 被**原始写死**在 config/app.yaml 4 条 URL（base_tile ×1 +
online_basemaps ×3）+ `online_basemap_templates._TIANDITU_TK` 常量副本，换一次 key 要改 5+ 处；
config 无 key 模型、无「改既有标量」写回原语（只有 append 条目）。

裁决（AskUserQuestion，均定稿）：
- 管理对象 = **按服务商集中管理**（弹窗列 provider，改一处全站生效），非逐条底图。
- 落盘 = **集中存独立段 + URL 用占位符引用**（`map.keys`，URL 里写 `{tk}`）。
- 覆盖 = **天地图（真实 tk，必须真生效）+ 高德（预留字段，URL 仍公开无 key，填了不影响加载）**。

## 架构关键

**占位符 `{tk}` 只在构建 QGIS 图层的边界替换，config 解析期永不替换。**
为什么必须这样：dock「模板已在树里置灰」与主窗口去重都按 url 判等——模板 def 与解析出的
config def 相比。若解析期就把 `{tk}` 替换成真 key，模板 `{tk}` vs config 真 key 永不等 →
已加模板被点亮、重复加不判重。两类 def 都保留 `{tk}`，判等自洽；只有发给 QGIS 的 uri 才替换。

`keys=None` → url 原样（单测/未接 key 的老数据）；`keys` 非 None → **无条件替换**（key 被
清空 → `tk=` 是诚实的"key 已清"状态，瓦片 403 而非静默用旧 key）。绝不在 dataclass 解析里替换。

## 做了什么

### 1. `app/env/config.py` — key 模型 + 新文本写回原语

`OnlineBasemapDef` 与 `MapConfig` 之间插 `MapKeysConfig`（frozen，`tianditu_tk`/`gaode_key`
默认 ""，`from_dict` None→""）；`MapConfig` 尾部加 defaulted `keys` 字段（MapConfig 只在
`from_dict` 构造，无位置传参，加尾字段安全——已 grep 全仓核实）。

新 `set_map_keys(path, keys)`：仿 `append_online_basemap_to_yaml` 的「只动目标行、保注释」哲学。
正则 `^map:\s*$` / `^(\s*)keys:\s*$` / `^(\s*)(tianditu_tk|gaode_key):\s*(.*)$`；定位顶层 `map:`
→ 子缩进（首非空非注释行，缺省 2）→ 找同缩进 `keys:`；无 → 整块插到 `map:` 后；有 → 只更新
两字段行（保留行前导缩进 + 行尾注释），缺字段在块尾补齐；块边界 = 首个缩进 ≤ keys 的行。

### 2. `app/core/domain/online_basemap_templates.py`

删 `_TIANDITU_TK` 常量；`_td_url()` 末尾 `&tk={tk}`（f-string 写 `{{tk}}` → 字面 `{tk}`）；
`_TIANDITU_REFERER/_TIANDITU_HOST` 保留。grep 确认全仓无其他 `_TIANDITU_TK` 引用。

### 3. `config/app.yaml`

`map:` 下插 `keys:` 块（含换 key 说明注释）+ 4 条 天地图 URL 尾部 `tk=cb75…` → `tk={tk}`。
真实 tk **只此一处**（单源）。referer/高德行/zmin/zmax 不动。

### 4. `app/core/domain/basemap.py` — 占位符替换 + keys 穿透

- 新纯函数（进 `__all__`）：`apply_key_placeholders(url, keys)`（None→原样；否则 replace
  `{tk}`/`{gaode_key}`）、`canonical_basemap_url(url)`（`re.sub(r"tk=[^&\s]+", "tk={tk}")`，
  只做判等归一、不改存储 url）。
- 5 个 builder 加可选参 `keys=None` 并在 url 边界 apply：`build_xyz_uri(tile, keys)` /
  `build_wms_uri(d, keys)` / `build_wmts_uri(d, keys)`（内传） / `build_base_tile_layer(tile,
  keys)` / `build_online_basemap_layer(d, keys)`（xyz→base 传 keys；arcgis→
  `QgsRasterLayer(apply_key_placeholders(d.url, keys), …)`；wms/wmts 传 keys）。
- `add_base_tile_layer(map_cfg)` **签名不变**，内部读 `map_cfg.keys` 传下去（启动 bootstrap:365
  与主窗口新建工程:775 自动受益，无需改调用点）。失败日志仍 `_mask_url(占位符 url)`。

### 5. 判等归一（两处去重点）

dock `_append_add_submenu` 的「已在树里置灰」与主窗口 `_add_online_basemap_template` 复合去重
（type,url,layers）比较前各过 `canonical_basemap_url`——老用户 config 仍内嵌真实 tk 的 url 与
`{tk}` 模板互认，去重不失效。

### 6. 新 `app/ui/dialogs/manage_keys.py` — `ManageKeysDialog(BaseDialog)`

`(parent=None, keys=None)`，无 config I/O（读写在 MainWindow）。`setMinimumSize(0,0)` +
`resize(520, 260)` + `setModal(True)`。天地图 tk / 高德 key 两个 QLineEdit（预填 keys）+
灰色 hint（天地图：换 key 影响所有 URL、已加载底图需重载；高德：预留、本轮不影响加载），
QDialogButtonBox Ok(→accept)|Cancel，访问器 `keys() -> MapKeysConfig`（strip 后组装）。

### 7. `app/ui/docks/online_basemap_dock.py`

构造加 `on_manage_keys`（存 `self._on_manage_keys`）；`_build_context_menu` 在「添加自定义底图」
后加分隔 + 顶层「管理 Key」；新 `_manage_keys()` 仿 `_add_custom()`（无回调返回 False）。

### 8. `app/ui/main_window/main_window.py`

- `_on_online_basemap` dock 构造加 `on_manage_keys=self._manage_basemap_keys`。
- 新 `_manage_basemap_keys()`：`_load_map_config()`（None → Critical + False）→
  `ManageKeysDialog(self, cfg.map.keys)` → exec 非 Accepted → False → `set_map_keys(...)`（异常
  → Critical + False）→ messageBar Info + logger（值打码 `***`）。
- `_add_online_basemap`（双击/叶子加载）：建层前重读 `_load_map_config()`，把 `cfg.map.keys` 传
  `build_online_basemap_layer(tile, keys)`——树里叶子 url 仍 `{tk}`，此处是唯一解析边界；刚改的
  key 对下一次添加立即生效。

## 踩坑

- **`yaml.safe_dump` 对根级标量补 `...` 文档结束标记行**：`_key_scalar` 最初
  `safe_dump(str(v)).strip()`，单行标量 dump 会产出 `值\n...\n`，拼成
  `tianditu_tk: xxx\n...`——`...` 结束整篇 YAML，其后缩进行全部解析报错（三个写回测试全红）。
  修复：`.rstrip("\n")` 后若以 `\n...` 结尾剥掉末尾 4 字符。（`_item_block` dump **映射**无此
  问题——块映射天然无需显式文档结束标记，故 append 老路径从未踩中。）
- **行尾注释的间隔空白丢失**：更新字段行时 `rest[rest.index("#"):]` 从 `#` 起截取，丢掉了值与
  `#` 之间的两个空格 → `tianditu_tk: 新tk# 注释`（`#` 前无空白不再算注释）。修复：从 `#` 位置
  向前回退连续空格，把「空格 + # 注释」整体当 tail。
- dialog 测试文件（`test_manage_keys.py`）不带 `@pytest.mark.gui`，会被 `-m gui` 静默跳过——回归
  时用不带 `-m gui` 的方式单独执行（与 test_custom_basemap.py 同病）。

## 遗留 / 注意

- referer 不动：天地图 browser-key 的 Referer 白名单域名仍各处独立 + 模板 `_TIANDITU_REFERER`
  （key 换绑的域名未来另做集中化）。
- 改 key 只影响**新建/重载**图层（已加载图层 source 建层时焊死），messageBar 文案已如实说明；
  不做热替换。
- 高德 key 仅预留字段，不影响当前加载（用户已确认）。
- `_mask_url` 只 mask `tk=`；未来别的高德 token 参数需另行扩展（本轮无）。
- 仓库 `config/app.yaml` 真实 tk 现**仅存** `map.keys.tianditu_tk` 一处（单源）；URL 全为 `{tk}`。
