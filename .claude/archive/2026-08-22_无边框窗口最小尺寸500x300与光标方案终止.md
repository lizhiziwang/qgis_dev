# 无边框窗口：最小尺寸 500×300 定稿，边缘缩放光标方案终止

## Context（为什么改）

用户在 [main_window.py](app/ui/main_window/main_window.py) 上提了两件事：
1. 无边框窗口边缘拖拽缩放时，鼠标光标要变成缩放光标（SizeHor/SizeVer/SizeFDiag）。
2. 窗口要设置最小宽高，最终确认为 **500×300**（宽 500、高 300）。

结论：最小尺寸做完了并保留；**光标方案被用户终止**（「算了鼠标样式不用改了」），
所有光标相关代码已全部还原。

## 一、最小尺寸 500×300（保留，已验证）

- [main_window.py](app/ui/main_window/main_window.py) `__init__`：`self.setMinimumSize(500, 300)`。
- [frameless.py](app/ui/common/frameless.py) `_wm_getminmaxinfo`：把 `ptMinTrackSize`
  填成 `minimumSize()` 的 dpr 换算值（Qt 是逻辑像素，WM 是物理像素，HiDPI 按
  `devicePixelRatioF()` 乘）→ 原生 SC_SIZE 缩放循环被系统钳制在下限之上。
- 两个文件编译通过（QGIS Python `py_compile`）。

## 二、光标方案终止（代码已全部还原）

探针实测确认的**结论性事实**，以后别再走这条弯路：

1. **WM_SETCURSOR 永远到不了 nativeEvent**。Qt6 的 `QWindowsWindow::windowProc`
   在真实鼠标移动时自己消费 WM_SETCURSOR（用来应用控件光标），真实移动中
   `nativeEvent` 只收到 WM_NCHITTEST（实测 3 条，WM_SETCURSOR 为 0）。
   → nativeEvent 拦 WM_SETCURSOR 改系统光标这条路不通。
2. **Qt 只在收到 WM_SETCURSOR（即鼠标移动）时才把控件 `setCursor` 渲染到屏幕**。
   鼠标静止时 setCursor 不刷新显示 → 窗口边缘悬停时「瞬移鼠标」后光标不更新。
3. **QTimer 轮询 + `widgetAt` + 延迟 `setCursor` 方案**：能正确调 setCursor，
   但静止时渲染有缺口；且 QTimer 的 0 延迟 `singleShot` 会跟控件/地图工具的
   setCursor 打架，光标在系统缩放光标与 Qt SizeHorCursor 之间抖动。未最终确认，
   用户已决定放弃。

**注意**：缩放机制本身（WM_NCHITTEST → WM_SYSCOMMAND(SC_SIZE) 编码修正）由
[[2026-08-21_无边框窗口鼠标缩放修复与模式开关主题适配]] 完成，与光标无关，功能完好。
