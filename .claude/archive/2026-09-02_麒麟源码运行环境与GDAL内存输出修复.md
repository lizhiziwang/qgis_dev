# 麒麟源码运行环境修复（QGIS 环境 / 配置 / GDAL 内存输出）

日期：2026-09-02

## 背景

麒麟 V10 真机（192.168.191.130）上直接跑源码版（`python app/main.py`，conda env
`qgis_new` = **QGIS 3.44.3 + PyQt5**）与已打包版（/opt/qgis_app，**QGIS 4.x + PyQt6**）
行为不一致，共暴露 3 个问题，本会话逐一修复：

1. 浏览器缺 PostgreSQL / XYZ 切片 / ArcGIS REST 服务节点（打包版正常）
2. `config/app.yaml` 的路径是 Windows 开发机路径，麒麟下无效
3. 分析工具（`gdal:*` 算法）执行报 `输出矢量无法加载：memory:融合 结果`

## 1. 浏览器数据源节点缺失

### 症状

源码版跑起来后，浏览器 dock 只有少量节点，缺 PostgreSQL / XYZ Tiles / ArcGIS REST
Servers；打包版节点齐全。

### 排查链

- `browser_dock.py` 是薄封装（`QgsBrowserGuiModel` + `QgsBrowserTreeView`），节点来自
  provider 插件注册，无自定义服务逻辑。
- 真机诊断：直接 `QgsApplication`（不设 prefix）→ provider 32 个全齐、`QgsBrowserGuiModel`
  rootItems 16 个全齐——**模型与 provider 本身没问题**。
- 走 bootstrap 真实路径（读 config → `QgisRuntime.for_dev("D:/zsh/app/qgis4.2")` →
  `apply_env` 设无效 `PROJ_DATA/GDAL_DATA/QGIS_PREFIX_PATH`）→
  `proj_get_authorities_from_database: Cannot find proj.db` → initQgis 部分失败 →
  浏览器节点异常。
- **根因**：`config/app.yaml` 的 `qgis.install_path: D:/zsh/app/qgis4.2` 是 Windows 开发机
  路径，麒麟上无效；打包版由 launcher 注入有效 `QGIS_PREFIX=/opt/qgis_app` 所以正常。

### 修复

- `QgisRuntime.for_system(prefix)`：新增 conda/apt **标准 Linux 布局**支持
  （`share/qgis`、`lib/qgis/plugins`、`share/proj`、`share/gdal`、`bin`），
  `_apply_system_env()` 设置对应环境变量。
- `bootstrap._build_qgis_runtime`：`QGIS_PREFIX` 存在时按目录布局自动识别——
  `apps/qgis` → for_prod（OSGeo4W）/ `proj.db` → for_portable（扁平便携）/
  `share/qgis` → for_system（conda 标准）。
- 新增 `tools/kylin/run_dev_kylin.sh`：一键源码运行（conda activate + `export
  QGIS_PREFIX=$CONDA_PREFIX` + `python app/main.py`）。

## 2. config/app.yaml 麒麟适配（环境变量引用 + 自动探测）

### 改动

- `config/app.yaml`：`qgis.install_path` 等改为 `${QGIS_INSTALL_PATH:-D:/zsh/app/qgis4.2}`
  形式——麒麟 `export QGIS_INSTALL_PATH=$CONDA_PREFIX` 即覆盖；Windows 不设变量走默认。
- `app/env/config.py`：新增 `_expand_env()` 解析 `${VAR}` / `${VAR:-默认}`（空变量也走
  默认），`_to_path()` 统一展开。
- `app/bootstrap/__init__.py`：新增 `_detect_linux_qgis()`——dev 分支下若 install_path
  不存在（Windows 路径在 Linux 上不存在）→ 自动探测：当前 conda 环境（`CONDA_PREFIX`）→
  常见位置 `qgis_new`（`~/miniconda3`、`/opt/conda` 等）→ 系统 apt `/usr`；
  校验 `share/qgis` + `share/proj/proj.db` 后走 for_system。

### 结果

麒麟上**什么都不设**直接 `python app/main.py` 即可正常（自动探测），
`run_dev_kylin.sh` 保留为显式、免探测的开销优化入口。

## 3. GDAL 算法内存输出修复

### 症状

分析工具跑 `gdal:dissolve` 报错：

```
RuntimeError: gdal:dissolve 输出矢量无法加载：memory:融合 结果
```

### 根因（QGIS 3.44 行为缺陷）

真机诊断 `processing.run("gdal:dissolve", {"INPUT": ..., "OUTPUT": "memory:融合 结果"})`：

- `results["OUTPUT"]` **原样透传字符串 `memory:融合 结果`**（不是图层对象）
- project 里**没有**创建任何结果图层——**数据根本没落盘**（GDAL 算法对 memory: sink 支持缺失）
- 不传 OUTPUT 又报 `Incorrect parameter value for OUTPUT`（GDAL 算法 OUTPUT 必填）
- 代码用 `"ogr"` provider 加载 `memory:` URI → 必然失败
- 打包版 QGIS 4.x 对 memory destination 处理正常，所以只有源码版报错

### 修复（`app/core/domain/generic_alg/service.py`）

- `_destination_value()`：OUTPUT 注入策略按算法类型区分——
  - 用户填了 output_path → 直接用（结果从路径 reload）
  - `native:*` → 保持 `memory:xxx`（原生内存 sink，返回图层对象）
  - **`gdal:*` → 注入临时文件路径**（`tempfile.mkdtemp` + `defaultFileExtension()`，
    栅格兜底 `.tif`、矢量兜底 `.gpkg`），跑完从文件加载成图层
- `_wrap_destination_result()`：加 memory: 字符串兜底——先找 project 同名图层复用，
  找不到明确报错（正常流程已不产生 memory: 字符串）
- 执行日志改显示实际注入的 OUTPUT 值（排查友好）

## 关键结论

- **QGIS 3.44（PyQt5）与 QGIS 4.x（PyQt6）行为差异是麒麟源码版问题的总根源**：
  方法级 API（如 `globalPosition()`，此前 qt_compat 已处理）和算法输出语义都可能不同，
  排查"源码版 vs 打包版不一致"时先确认两边 QGIS 版本。
- **GDAL 算法永远别给 `memory:` destination**（QGIS 3.x 至少 3.44 不落盘）；
  native 算法才支持内存 sink。
- conda 的 QGIS 是标准 Linux 布局（`share/qgis`），不是 OSGeo4W 布局，
  运行时前缀即 `$CONDA_PREFIX`。
