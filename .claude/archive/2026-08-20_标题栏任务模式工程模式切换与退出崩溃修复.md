# 标题栏任务/工程模式切换 + 两个原生崩溃修复

## Context（为什么改）

用户要求：「主题选择后面再加一个切换switch开关功能。左边是任务模式，
右边是工程模式」（[title_bar.py](app/ui/main_window/title_bar.py)）。

同时本次收尾排查发现两个历史原生崩溃（均与测试 / 关闭路径相关）：
1. **悬空 messageBar 指针**：MainWindow 把 `self.messageBar` 塞进
   `QgsApplication` 全局属性后不清理，窗口被 GC 后属性里残留的
   `QgsMessageBar*` 是悬空指针，任何后续 `send()` 访问
   `property("messageBar")` 就 native access violation。
2. **解释器退出时 0xC0000409**：只要构造过 MainWindow，进程退出时必
   `STATUS_STACK_BUFFER_OVERRUN` 崩溃，pytest 停在 `[100%]` 打不出汇总行。

## 方案

### 1. 标题栏模式开关 `_ModeSwitch`（title_bar.py）

胶囊分段控件（左右各一个按钮 + 独占 QButtonGroup）：

```python
MODE_TASK = "task"
MODE_PROJECT = "project"          # 默认
_MODE_OPTIONS = [(MODE_TASK, "任务模式"), (MODE_PROJECT, "工程模式")]

class _ModeSwitch(QWidget):
    mode_changed = pyqtSignal(str)
    # QButtonGroup(self) + setExclusive(True)；idClicked → _on_id_clicked
    # mode property / set_mode(key, emit=True) / apply_theme(theme)
```

- 按钮背景用 `theme.menu_bg` 轨道 + `theme.border` 描边，选中态
  `theme.input_focus` 背景 + 白字，hover 用 `theme.menu_hover`（跟随主题）
- TitleBar 暴露 `mode_changed = pyqtSignal(str)`，把 `_ModeSwitch.mode_changed`
  转发出去；`_apply_theme` 同步调 `_ModeSwitch.apply_theme`
- `_ModeSwitch` 加进 `_interactive` 列表（无边框窗口拖动 / hover 行为统一）

### 2. 悬空 messageBar 修复（main_window.py）

构造时仍设全局属性（兼容旧 `sendMessageToTopParent`），但加双向清理：

```python
qgis_app.setProperty("messageBar", self.messageBar)
self.destroyed.connect(self._clear_global_messagebar)

def closeEvent(self, event: QCloseEvent) -> None:
    try:
        self.project.clear()
    finally:
        self._clear_global_messagebar()
        event.accept()

def _clear_global_messagebar(self, *args) -> None:
    qgis_app = QgsApplication.instance()
    if qgis_app is None:
        return
    try:
        qgis_app.setProperty("messageBar", None)
    except RuntimeError:
        pass  # 对象已部分销毁，残留交给 Qt 自身兜底
```

`closeEvent` 覆盖「用户主动关闭」，`destroyed` 信号覆盖「被 GC / deleteLater
销毁」，两条路径都清属性，防悬空指针。

### 3. 退出 0xC0000409 修复（tests/ui/conftest.py）

探针定位：**只构造一个 MainWindow 就必现**退出崩溃；`close()` 不够（只隐藏
不销毁 C++ 对象），`sip.delete(w)` 立即干净。根因是 MainWindow 的 Python
wrapper 因 `messageBar` 属性持有 Qt 侧引用而形成引用环，存活到解释器终结
阶段才被 GC——此时 `QgsApplication` 已在析构，C++ QWidget 析构触发 failfast。

会话收尾加显式销毁（`qgis_app` session fixture teardown）：

```python
from PyQt6 import sip
from PyQt6.QtWidgets import QApplication

for w in list(QApplication.topLevelWidgets()):
    try:
        sip.delete(w)
    except RuntimeError:
        pass
try:
    app.exitQgis()
except Exception:
    pass
```

## 关键 API 备忘

- **`QButtonGroup` + `idClicked`**：实现二态分段开关；`setExclusive(True)`
  保证互斥，`idClicked` 拿点击的按钮 id（配合 `setId(btn, value)`）
- **`QgsMessageBar*` 进 QVariant 属性**：PyQt 的 `setProperty("x", qobject)`
  用 `PyQt_PyObject` 存强引用。属性不清理，wrapper 活到终结阶段 → 引用环
  让 MainWindow 逃过 refcount，延后到 GC。这就是退出崩溃的直接机制
- **`sip.delete(w)` vs `w.close()`**：`close()` 只隐藏（除非
  `WA_DeleteOnClose`），C++ 对象仍在；`sip.delete` 立即销毁 C++ + 作废
  wrapper，是测试里主动释放 QWidget 的正确手段
- **0xC0000409 的 exit code**：`-1073740791`（STATUS_STACK_BUFFER_OVERRUN，
  `__fastfail`），Windows 上 Qt/QGIS 析构顺序错乱时的典型失败信号

## 风险与限制

- **conftest 收尾只影响 ui 测试**：`tests/ui/conftest.py` 的 `qgis_app` 是
  session 级；core 各 domain 有自己的 conftest（同名 `qgis_app`），不共享
- **`exitQgis()` 包 try/except**：收尾异常不掩盖测试结果；`sip.delete` 也
  包 RuntimeError（widget 可能已被释放）
- **`_clear_global_messagebar(*args)` 的 `args`**：`destroyed` 信号槽签名
  需要接收 `QObject*`，`*args` 是故意的（IDE 的"未存取"提示可忽略）
- **未做（留待后续）**：`_ModeSwitch` 目前只有 UI + 信号，尚未接任何业务
  逻辑（任务/工程模式的具体行为差异由下游消费者订阅 `mode_changed` 实现）
