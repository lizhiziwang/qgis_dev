# 天地图缩放白屏：预取当前视口 + refresh 重绘（无 freeze 版）

> 2026-09-04 归档
> 续 `2026-08-28_天地图底图白屏分析与后台瓦片预热.md`

## Context

天地图 XYZ 底图在缩放/平移时出现白屏。根因不变：XYZ provider 取瓦片是**同步网络请求**，
渲染线程阻塞于网络；QGIS 4 画布渲染期间显示纯白，瓦片到齐才出图。

**前方案（邻居预热）** 的局限：
- `renderComplete` 后再预热 8 个**邻居视口** —— 预热的是"下一次"位置
- 当前缩放位置本身仍要走"渲染→等瓦片→白屏"的流程
- 用户体感："缩放后总要白一下"

**本方案目标**：让缩放**连续无 snap**。不冻结画布、不回退到旧帧；画布直接出当前
extent（瓦片未到就白），后台预取当前视口瓦片进缓存，瓦片就绪后 `refresh()` 把白
填上——视觉上是连续的"瓦片逐个到位"，没有"先回退到旧帧再突然跳到新帧"的 snap。

## 改动总览

### 1. `app/core/domain/tile_prefetch.py`（核心改造）

**A. `_PrefetchWorker` 增加完成通知**

`submit(items, template)` → `submit(items, template, completion_event=None)`：
worker 处理完一轮（队列空）时 `event.set()`，主线程轮询。

**B. 新增 `ZoomTileGuard(QObject)` 类**（[tile_prefetch.py:333](../app/core/domain/tile_prefetch.py#L333)）

挂在主画布上，extentsChanged 时后台预取当前视口瓦片，瓦片就绪后 `refresh()` 重绘。
**不冻结画布**——上一版（commit `fc9fee7` 之后）用 `freeze(True)/(False)` 实现的
"snap 跳变"被用户反馈不平滑，本版拿掉 freeze，只保留预取 + refresh。

关键字段：
- `_seq`：取消旧预取用（连续缩放时递增，旧 event 即使 set 也不被采纳）
- `_pending_event` / `_pending_seq`：当前正在等待的批次
- `_worker`：独立 worker（不与 TilePrefetcher 共享——见下）

关键方法：
- `_on_extents_changed`：seq++、停轮询、重启 debounce
- `_on_idle`：防抖到期 → 提交预取 → 启动轮询
- `_on_poll`：检查 event / 超时 → `_refresh`
- `_refresh`：`canvas.refresh()`（瓦片已在缓存，渲染不阻塞网络）

### 2. `app/ui/main_window/main_window.py`（集成）

在创建 `TilePrefetcher` 旁添加 `ZoomTileGuard`：

```python
from app.core.domain.tile_prefetch import TilePrefetcher, ZoomTileGuard

self._tile_prefetcher = TilePrefetcher(self.canvas, project=self.project, parent=self)
self._zoom_tile_guard = ZoomTileGuard(self.canvas, project=self.project, parent=self)
```

`closeEvent` 中（`project.clear()` 之前）调用 `guard.shutdown()`。

### 3. 根分组渲染顺序（解决"慢速矢量图层拖住底图"）

`_on_project_create`（[main_window.py:700-708](../app/ui/main_window/main_window.py#L700)）
调整建组顺序——参考图层（底图）放根分组**底部**（先渲染），数据图层放**顶部**（后渲
染、盖在底图上）。QGIS 按 layer tree 索引升序渲染，原来反了导致底图被排在最后渲染，
慢速矢量图层渲染期间看不到底图。

`_on_open_project` 同步加了兜底：老工程打开时把参考图层强制挪到根底。

## 关键工程细节

### worker 实例独立

ZoomTileGuard **不**与 TilePrefetcher 共享 worker：
- `submit()` 替换队列的语义下，共享会让邻居预热被当前预热打断（行为正确但不利分析）
- 多一个 daemon 线程空闲挂 condition variable，开销可忽略

### 取消旧预取（seq 计数器）

连续缩放场景：debounce 重置 → `_on_extents_changed` 把 `_seq += 1` → 旧 event 即使被
worker set 了，poll 时 `_pending_seq != self._seq` 也会被忽略。配合 `_pending_event = None`
防止脏 event 干扰下次 idle。

### debounce vs 单次提交

debounce 期间持续缩放会让旧预取自然过期（seq 递增、event 被忽略）。一旦停下来 200ms
立即预取并轮询；硬超时 2s 兜底（避免网络卡死时 refresh 永远不调——但因为没冻结，画布
仍会按 extentsChanged 直接渲染，所以兜底只是防止"refresh 永远不调"，不至于画面卡死）。

### 跨线程信号

worker 在 daemon 线程，event 是 `threading.Event`（跨线程安全）。poll 在主线程
（`QTimer`），避免 Qt signal 的 queued connection 复杂性。

## 设计权衡（去 freeze 的代价）

| | freeze 版（已弃） | 现版（无 freeze） |
|---|---|---|
| 旧帧回退 | 有（"突然回到缩放前"） | 无 |
| 首屏白屏 | 无 | 可能有（瓦片未到时该位置白） |
| 缩放体验 | snap：旧→新 | 连续：新（白）→新（瓦片到位） |
| 复杂度 | 多一个 freeze 状态机 | 简单 |

用户反馈"不平滑，会先突然回到缩放前的状态"——这是 freeze 的物理后果，本质就是个
snap，freeze 多久都无法消除。现版接受"首屏白屏可能回来"换取"无 snap"。

如果白屏明显，下一步可以用占位灰（`QgsMapSettings.setBackgroundColor` 或
`QgsRasterLayer.setBackgroundColor`）代替纯白——视觉上比白屏柔和，但需要进一步
验证 XYZ provider 是否会覆盖 backgroundColor。

## QGIS 4.2 PyQt6 API 注意（已实测 / 已踩坑）

| 坑 | 实际 API | 错误写法 |
|---|---|---|
| **信号名带 s** | `canvas.extentsChanged` | `canvas.extentChanged` |
| 冻结状态查询 | `canvas.isFrozen()` | — |
| 冻结状态变化信号 | `canvas.freezeStateChanged(bool)` | — |

代码库里 `swipe.py:347`、`qmap_compare.py:437` 等都是 `extentsChanged` 写法。

去 freeze 后不再需要 `canvas.freeze(True)/(False)`，也不需要监听 `renderComplete`
做"首次渲染前不冻结"的保护。

## 后续可选优化

- **占位灰代替纯白**：未缓存瓦片位置用柔和灰色填充，视觉上比白屏舒适
- **预渲染多 extent**：除了当前视口，额外预渲染相邻 4 个视口——zoom 一次可能直接落在另一层
- **自适应超时**：根据网络延迟历史动态调 `_TIMEOUT_MS`
