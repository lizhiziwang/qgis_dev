# 分析工具增加「最小外包矩形」

## Context（为什么改）

`app/ui/docks/analyse_dock.py`（实际是 `tools_dock.py` 的别名）的「矢量分析」分组
当前提供 4 个工具：缓冲区、叠加、最短路径、重投影。用户希望在矢量分析窗口里
加一个 QGIS 自带的 `native:orientedminimumboundingbox` 算法处理 —— 按面积最小化
给每个要素生成方向最小化的外包矩形面，常用于描述建筑物主轴、农田垄向等
"最佳朝向"边界。

通过 AskUserQuestion 选了 **「完整对话框」**：参数面板 + 进度条 + processing.run
+ 结果加进项目 + 画布刷新，与 BufferDialog 风格一致。

## 方案

沿用仓库既有的 `BufferService` / `BufferDialog` 三段式（service 门面 + dialog UI +
注册到 tools_dock），算法只有 INPUT + OUTPUT 两个参数（其它字段由算法自动注入），
所以 dialog 不需要复杂参数面板。

### 1. `app/core/domain/oriented_bbox/service.py` — 服务门面

`OrientedBBoxJob`（frozen dataclass：layer/output_name/output_path）+ `OrientedBBoxService.run()`，
调用 `processing.run("native:orientedminimumboundingbox", {"INPUT": widened_layer, "OUTPUT": memory|file}, ...)`。
复用 `copy_with_widened_string_fields` 兜底 GDB/ArcGIS 脏数据；输出文件路径模式
从文件 reload（与 BufferService 一致）。

### 2. `app/ui/dialogs/oriented_bbox.py` — Dialog

参照 `app/ui/dialogs/buffer.py`：
- 左侧参数面板：输入图层 QComboBox（仅矢量）+ 输出图层名 + 输出文件路径（留空为临时缓存）
- 右侧算法描述（`make_description_browser("native:orientedminimumboundingbox")`，自动用 processing 注册表的真实说明，**处理插件未加载时**回退到 `_ALGO_FALLBACK_DESC` 兜底文案 —— 必须新加 key，否则显示 "native:orientedminimumboundingbox" 裸字符串）
- 底部 QProgressBar + 执行/关闭
- `_on_execute()` 通过 `QTimer.singleShot(0, ...)` 把 processing.run 推迟到事件栈外执行
  —— 直接在 clicked 信号栈里跑 `processing.run` + `addMapLayer` + `canvas.refresh`
  会原生崩溃 `0xC0000409`（与 BufferDialog 同坑：feedback→progress→native cross-thread
  渲染，无 Python 异常可捕获）
- 完成后自动 `project.addMapLayer`、发 messagebar 成功提示、refresh 画布

### 3. `app/ui/docks/tools_dock.py` — 注册

- 新加 `_make_oriented_bbox_dialog(parent)` 工厂（懒 import）
- `_DIALOG_FACTORIES["native:orientedminimumboundingbox"]` 登记
- `_TOOL_TIPS["native:orientedminimumboundingbox"]` 加说明
- `_TOOL_GROUPS` 「矢量分析」分组下加 `("最小外包矩形", "native:orientedminimumboundingbox")`

### 4. `app/ui/common/algo_desc.py` — 兜底文案

`_ALGO_FALLBACK_DESC["native:orientedminimumboundingbox"]` 加中文 HTML 说明，
字段列表写实际产物（angle / area / perimeter / width / height），不是
"rotated_rect"（实测本构建不输出该字段，写了会误导）。

### 5. `tests/ui/docks/test_tools_dock.py` — 回归

- 新增 `test_oriented_bbox_registered_in_tool_tree`：工厂存在 + tooltip 存在 +
  树分组正确 + factory 能产出 `OrientedBBoxDialog` 且 `windowTitle()=="最小外包矩形"`
- 新增 `test_oriented_bbox_runs_on_memory_layer`：端到端 happy path —— 直接调
  `OrientedBBoxService` 在内存图层跑通，结果图层 featureCount==1 且包含
  `{angle, area, height, perimeter, width}` 字段。**关键**：测试内调
  `Processing.initialize()`，否则 `processing.run` 会抛
  `QgsNotSupportedException("Processing plugin has not been loaded")`
  （与 `tests/core/domain/buffer/test_service.py::test_buffer_succeeds_on_real_gdb`
  同样的兜底）
- 顺手修复 `test_different_tools_get_different_dialogs` 的 pre-existing bug：
  之前断言 `len(dock._dialogs) == len(leaf_items)` 会因 `flow:editor`
  在 `_SIMPLE_ACTIONS` 不在 `_DIALOG_FACTORIES` 而少 1。改为只统计
  "在 `_DIALOG_FACTORIES` 内的叶子"，过滤掉简单动作类工具

## 已知限制 / 备忘

- 算法按要素生成，故输入图层为空（featureCount==0）会得到空结果图层（不是 bug）
- 结果图层只追加，不替换。如果同名图层已在工程里，`addMapLayer` 会自动重命名为
  "最小外包矩形结果 (1)" 等，与现有约定一致
- 字段说明以 `processing.run` 实测结果为准 —— 不要相信文档或源代码注释里写的
  "rotated_rect"，本构建（QGIS 4.2.0-Belém do Pará）实际输出的是 angle 字段
