# 无边框窗口鼠标缩放修复 + 模式开关主题适配

## Context（为什么改）

1. 用户报：「应用程序无法通过鼠标拖拽控制窗口的大小」（[main_window.py](app/ui/main_window/main_window.py)）。
   Windows 无边框窗口边缘缩放失效。
2. 顺带确认 Linux 缩放适配是否就绪。
3. 用户报：切到蓝色主题后，标题栏「任务/工程模式」切换按钮跟主题同色、看不清选中态
   （[title_bar.py](app/ui/main_window/title_bar.py)）。

## 一、Windows 缩放根因与修复（frameless.py）

**根因**：无边框窗口下 Qt 的窗口过程收到 `WM_NCLBUTTONDOWN(wParam=HT*)` 不会启动系统
resize 循环（缩放码被 Qt 丢弃）。`WM_NCHITTEST` 命中判定本身是对的（探针实测各边缘
返回 10..17 全部正确）。

**修复**：`nativeEvent` 在 `WM_NCLBUTTONDOWN` 时对 `_SIZE_HT_CODES` 分支
`ReleaseCapture()` + 重发 `WM_SYSCOMMAND(SC_SIZE|方向)`，让系统接管缩放循环。

**SC_SIZE 编码坑（重点）**：`SC_SIZE = 0xF000`，系统按 `wParam & 0xFFF0` 取命令。
不能 `SC_SIZE | HTBOTTOMRIGHT(17)` → `0xF011 & 0xFFF0 = 0xF010 = SC_MOVE`，缩放被
当成拖动。方向编号与 HT 码错一位：HTLEFT..HTBOTTOMRIGHT(10..17) → 方向 1..8。
纯函数 `sc_size_wparam(ht) = SC_SIZE | (ht - 9)`，方向映射经暴力探针实测确认
（sc1=左、2=右、3=上、4=左上、5=右上、6=下、7=左下、8=右下）。

**探针坑**：`SendInput` 相对移动（无 `MOUSEEVENTF_ABSOLUTE`）的 dx/dy 是「mickey」
不是像素，受控制面板鼠标速度/加速放大（本机约 5.8×）。左/上边缘「塌缩到 2px」全是
相对移动过冲的探针伪影；换绝对坐标后不再塌缩。注入同步 modal resize 循环天然不稳，
端到端验证以用户真鼠标为准（用户已确认「缩放可以了」）。

## 二、Linux 适配评估（无改动，已就绪）

- **拖动**：TitleBar 用 `QWindow.startSystemMove()`（Qt 5.15+ 原生，X11
  `_NET_WM_MOVERESIZE` / Wayland 交互移动），兜底 `window().move()`。
- **边缘缩放**：MainWindow（main_window.py:172）与 FlowWindow（window.py:68）都调
  `monitor_resize_edges(canvas/view)` 注册目标；`FramelessMixin.eventFilter` 命中边缘
  → `QWindow.startSystemResize(edges)`（X11 原生 / Wayland `xdg_toplevel.resize`），
  失败回退 `grabMouse` + `_continue_manual_resize`。
- Windows 修复全部在 `_is_windows()` 分支内，不影响 Linux。无法在 Windows 开发机
  真跑 Linux 冒烟，代码路径已完整。

## 三、模式开关主题适配（title_bar.py）

用户报了两层问题（蓝色主题下），根因是三层，全部修掉：

**根因 1（轨道不渲染）**：`_ModeSwitch` 是普通 QWidget，QSS 的 `background-color` /
`border` 必须开 `WA_StyledBackground` 才渲染，而它没设 → 容器「轨道」一直透明。

**根因 2（未选中段透明）**：未选中按钮底色是 `transparent`。蓝/绿主题的标题栏是主题
主色（`title_bg`），标题栏色从按钮后透出 → 选中段和未选中段看起来都像主题色，
看不出哪个被选中。

**根因 3（选中段与标题栏同色）**：蓝/绿主题 `input_focus == title_bg`
（`#2f5f8f` / `#2e7d5b`，标题栏即主题主色）。选中段用 `input_focus` 直接坐在
同色标题栏上 = 隐形。浅/深主题碰巧 `input_focus != title_bg` 所以没暴露。

**修复**（`_mode_switch_qss` / `_ModeSwitch.__init__`）：

1. 容器 `setAttribute(WA_StyledBackground, True)` → 轨道渲染出来。
2. 未选中按钮底色从 `transparent` 改为 `menu_bg`（轨道色），文字用 `menu_text` →
   不再透出标题栏色。
3. 选中段：`sel_bg = input_focus`，当 `input_focus == title_bg` 时回退到深色
   `menu_text` 打底（白字照常）→ 选中段在所有主题下都与标题栏形成对比。

最终配色（蓝/绿主题）：未选中段 `menu_bg`（蓝 `#eef3fa` / 绿 `#eaf5ee`），选中段
`menu_text`（蓝 `#1f3a5c` / 绿 `#1f3a2c`），两者都与各自 `title_bg`（`#2f5f8f` /
`#2e7d5b`）不同。浅/深主题照常走 `input_focus`（`input_focus != title_bg`）。

## 测试

- `tests/ui/test_frameless.py` 新增 9 个纯函数测试（20 全过）：
  `sc_size_wparam` 命令位必须仍是 SC_SIZE（非 SC_MOVE）+ 8 个方向映射；
  `_continue_manual_resize` 手动兜底几何（左右上下四边 + 两角 + 无 edges no-op）。
- `tests/ui/main_window/test_title_bar.py`（本次新增的未跟踪文件）9 个全过，其中本次
  新增：容器必须开 WA_StyledBackground（`test_mode_switch_container_renders_background`）；
  蓝主题下选中段不用与标题栏同色的 `input_focus`、改用 `menu_text` 且 `menu_bg` 轨道色
  必须在 QSS 里（`test_mode_switch_blue_theme_selected_differs_from_title_bar`）；
  纯函数校验 `_mode_switch_qss`：所有主题选中段 ≠ `title_bg`，`input_focus == title_bg`
  时回退 `menu_text`，彩色主题未选中段 ≠ `title_bg`
  （`test_mode_switch_qss_selected_differs_from_title_bar`）。
- 回归：`tests/ui/main_window/ + tests/ui/test_frameless.py` 53 passed；
  已知 4 个失败与本次改动无关（shortestpath 代价 2226389 vs 20 为算法/数据问题，
  flow_editor smoke 单独跑通过 = 批处理状态污染）。
