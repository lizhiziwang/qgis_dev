# 属性表过滤在大数据量下卡死 —— 后台线程流式过滤

> 2026-08-17。前置：`2026-08-14_属性表500w流式加载.md` 已解决无过滤滚动加载，
> 但**过滤**路径仍在主线程同步全表扫描，500w 级矢量直接卡死 UI。

## 冻结源（真实 QGIS 4.2 探针确认）

1. **选择性过滤 = 主线程全表同步扫描**：填充首屏时过滤表达式对每个要素逐条求值直到攒满一批。
   300k 匹配 ~300 条 0.17s → 500w 级 memory ~3s、真实 shapefile 数十秒。匹配很少/为 0 时最严重（要扫完整张表）。
2. **`show_ids` 走 `$id in (N 个 id)` 表达式：O(要素数 × N)**。实测 300k 图层 + 1000 fids = **40 秒**。

## 方案

过滤/流式迭代挪到**后台线程**（`FeatureStreamWorker`，普通 `threading.Thread` + Qt 队列信号，
不用 QgsTask——见 `app/core/domain/imagery_tiles/task.py` 退出码 127 的坑）；`show_ids` 改用
`setFilterFids` 快路径。改动文件：

- `app/ui/docks/attribute_dock.py` —— 核心：新增 `FeatureStreamWorker`（工作线程迭代、按 target
  暂停、`chunk_ready`/`finished`/`paused` 信号、epoch 丢弃过期在途信号、`cancel_stream`）；
  `PagedAttributeTableModel` 异步化；widget 增加"正在加载/已停止加载"状态文案；编辑开始/关闭/
  换图层时 `cancel_stream()`。
- `app/ui/dialogs/query_builder.py` —— "测试条件"计数同样主线程全表扫描，改为 `_SqlCountWorker`
  后台计数，按钮禁用+"查询中…"。
- `tests/ui/docks/test_attribute_dock.py` —— 流式路径测试改用 `_pump` 轮询事件队列；新增
  show_ids 组合/取消/扫描态用例。16 个全部通过。

## 三个关键 QGIS 4.2 API 事实（踩坑记录）

1. **`setFilterFids` 与 `setFilterExpression` 不能组合**（探针实测，两种顺序都只有最后一个生效）：
   `setFilterExpression` 内部清空已设 fids；fids 快路径也忽略表达式。show_ids + 表达式组合时，
   以 `setFilterFids` 为主过滤（范围受 show_ids 大小约束，非全表），表达式在 worker 里逐条求值
   （`QgsExpression` + `QgsExpressionContext`，`globalProjectLayerScopes`）。
2. **`setFilterFids` 返回顺序是 QSet 哈希序，进程间不稳定** —— 测试不能断言具体 id 顺序。
3. **批次边界耗尽探测**：停在整批倍数（120 条/批 24）的图层，若 worker 不"多取 1 条"探测
   StopIteration，`has_more` 永远为 True。用 `_stashed` 暂存探测要素到下一轮（不能直接发出，
   否则 `rowCount == batch` 的断言会因多 1 条失败）。

## 性能验证（300k memory 图层，`perf_probe.py` 已删）

- 过滤 `"name"='name-777'`（匹配 1 条，需扫全表）：构造返回 0.000s（GUI 不阻塞），首行 0.171s。
- 1000 fids show_ids：0.000s（旧 `$id in (...)` 40s）。
