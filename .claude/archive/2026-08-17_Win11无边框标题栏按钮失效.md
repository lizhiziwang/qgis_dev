# 2026-08-17 Win11 无边框窗口标题栏按钮失效修复

## 背景

用户反馈：Win11 系统下主窗口（`MainWindow`）边框上的按钮不起作用 —— 点最小化/
最大化/关闭/主题/用户按钮没反应。拖动与缩放（依赖 `WM_NCHITTEST` 返回
`HTCAPTION` / resize 码）正常。

## 根因

无边框窗口靠 `FramelessMixin.nativeEvent` 拦截 `WM_NCHITTEST`（`0x0084`）决定
该像素属于哪种系统命中：

- 按钮区 → 应返回 `HTCLIENT`，Qt 正常收到鼠标点击；
- 标题栏空白 → 返回 `HTCAPTION`，系统接管窗口拖动（含贴边吸附）；
- 窗口边缘 → 返回 `HTLEFT`…`HTBOTTOMRIGHT`，系统接管缩放。

原实现 `app/ui/common/frameless.py::_wm_nchittest` 两个缺陷叠加导致按钮区被误判
为拖动区，点击被系统当作拖动吃掉：

1. **`QApplication.widgetAt(物理坐标)` 全局查询脆弱**：`WM_NCHITTEST` 的
   `lParam` 是**物理像素**屏幕坐标，而 Qt 的 `widgetAt` 按**逻辑像素**解释。
   Win11 在 110%~150% 缩放下两者错位，`widgetAt` 可能返回 None 或错位控件，
   使按钮区落入 `tb` 判定分支并被当成非交互 → 误判 `HTCAPTION`。
2. **边缘/空白区判定同样物理/逻辑混用**：`y <= top + m` 等用物理 y 与逻辑
   `frameGeometry()` 的 top/bottom 直接比较，HiDPI 下边缘缩放阈值也错位。

（探针曾假设"纯 HiDPI 必然坏"——经真实窗口验证被推翻：dpr=1.5 时 `widgetAt`
返回 None → 落 `HTCLIENT`，按钮反而正常，坏的是拖动。真正脆弱的是 1.25 附近
错位控件 + 平台行为差异，故仍按几何命中 + DPI 换算稳健修复。）

## 做了什么

**`app/ui/main_window/title_bar.py`**：新增公开方法

```python
def is_interactive_pos(self, pos: QPoint) -> bool:
    """pos（标题栏本地坐标）是否落在任一可交互控件几何内。"""
    return any(child.geometry().contains(pos) for child in self._interactive)
```

纯子控件几何命中，不依赖 `QApplication.widgetAt`。（原私有 `_is_interactive_pos`
保留给非 Windows 鼠标拖动兜底，两者一致。）

**`app/ui/common/frameless.py::_wm_nchittest`**：
1. 消息坐标解析后立即按 `self.devicePixelRatioF()` 物理→逻辑换算
   （`round(x / ratio)`；dpr=1 时退化为恒等，不影响 dev 机）；
2. 用 `tb.is_interactive_pos(tb.mapFromGlobal(逻辑坐标))` 几何命中替代
   `QApplication.widgetAt` + `is_interactive_child` 全局查询，并加
   `not tb.isHidden()` 保护。

`MainWindow` / `FlowEditorWindow` 均未本地覆写 `_wm_nchittest`，直接复用 mixin
修复。

## 关键结果

探针构造真实窗口 + 合成 `WM_NCHITTEST` 消息直接调用修复后的 `_wm_nchittest`：

| 判定点 | dpr=1.0（真实） | 模拟 1.25× | 模拟 1.5× |
|---|---|---|---|
| min/max/close/theme/user 按钮 | HTCLIENT(1) ✓ | ✓ | ✓ |
| 标题栏空白区 | HTCAPTION(2) ✓（可拖动） | ✓ | ✓ |
| 顶部/右侧/右下边缘 | 12/11/17 ✓（可缩放） | ✓ | ✓ |

真实点击冒烟：`QTest.mouseClick(关闭按钮)` → `close_requested` 信号触发，按钮
点击不被 `HTCAPTION` 吃掉。全部 `ALL_PASS`。改动前后 `py_compile` 语法通过，
`is_interactive_child` 保留未删，向后兼容。

## 遗留事项

- dev 机 100% 缩放（dpr=1.0）无法复现 Win11 真实故障现场，逻辑判定已通过
  HiDPI 模拟全覆盖；**需用户在 Win11 高分屏机器上实测按钮点击/拖动/缩放**。
- 若实测仍异常，下一个排查点：`WM_NCHITTEST` 之外 Win11 对无边框窗口的
  `WM_NCLBUTTONDOWN(HTCAPTION)` 重发是否被 DWM 拦截，以及 `frameGeometry()`
  在 DPI 感知进程里是否等于 `geometry()`。
