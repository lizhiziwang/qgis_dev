# 2026-08-28 天地图底图白屏分析与后台瓦片预热

## 需求

`app/ui/tools/qmap_compare.py` 放大后拖动导致白屏，先定位根因再修复。结论：
与分屏工具无关，是天地图 XYZ 底图渲染时**同步取瓦片**（渲染线程阻塞于网络），
QGIS 4.2 画布渲染期间（`isDrawing()`）显示纯白；拖动释放后新视口瓦片未缓存，
白屏持续到瓦片到齐。修复方案：**后台瓦片预热** —— 画布渲染完成后离屏预渲染
四周 ±1 视口，提前把瓦片拉进缓存，消除拖动/放大后的白屏。

## 改动

- `app/core/domain/tile_prefetch.py`（新，核心）：
  - `TilePrefetcher(QObject)`：连接 `canvas.renderComplete` → 800ms 防抖
    `QTimer` → `_schedule_round` → 构建 8 个相邻视口 extent（4 正方向优先，
    量化去重 `_extent_key`，cap 256）→ 提交后台 `_PrefetchWorker`。
  - `_PrefetchWorker(threading.Thread, daemon=True)`：串行渲染
    （`QgsMapRendererCustomPainterJob` + `waitForFinished`），`Condition` 同步，
    `submit()` 可替换队列（只保留最新一轮），`stop()` 安全退出。
  - 限额 `max_round_tiles=128` / `max_extent_tiles=96`，防全景时拉上千瓦片。
  - `shutdown()` 绑在 `canvas.destroyed`。
- `app/ui/main_window/main_window.py`：canvas 创建后实例化
  `TilePrefetcher(self.canvas, project=self.project, parent=self)`。

## 关键设计 / 非显然点（QGIS 4.2 PyQt6 实证）

1. **根因**：XYZ provider 取瓦片是同步网络请求，发生在渲染线程内 → 渲染期间
   画布 `isDrawing()` 为 True 时抓帧纯白 `(255,255,255)`；矢量层渲染瞬间完成
   故无白屏。对照组（未预热）平移一屏白屏 1.5s，预热后 **0 白屏**。

2. **渲染设置必须拷贝 `canvas.mapSettings()`**（`QgsMapSettings(canvas.mapSettings())`）
   再 `setExtent` / `setLayers`，不能从零构建：
   - 画布设置里带好图层变换/变换上下文，xyz provider 才能把 4490 extent 正确
     重投影到 EPSG:3857 选瓦片；
   - 缺变换上下文时 provider 把 4490 度数当 3857 米算瓦片号，8 个 extent 全部
     命中原点附近同一张瓦片 `(8192,8191)@z14` —— **这是排查指纹**。

3. **预热渲染输出尺寸 = 画布实际 `outputSize()`**（不缩小）：XYZ provider 按
   渲染分辨率选瓦片层级 z，尺寸变小会选低一级 z，预热瓦片对不上画布要用的。

4. QGIS 4.2 PyQt6 绑定差异（与 QGIS3 不同，项目现有代码也用扁平枚举）：
   - `QgsMapLayer.Type.RasterLayer` → `QgsMapLayer.RasterLayer`（否则
     `_schedule_round` 早退不预热）；
   - `QgsMapSettings.setProject(...)` **不存在**（已移除）；
   - `QgsMapRendererQImageJob` **无法实例化**（"cannot be instantiated or
     sub-classed"），改用 `QgsMapRendererCustomPainterJob` + 显式 QImage/QPainter；
   - `waitForFinished()` 返回 None（void）；
   - 后台线程用 Python `threading.Thread`(daemon) 而非 QThread：规避 QThread
     销毁告警/崩溃风险；probe 证明从 python 线程 start/wait 离屏渲染 job 可用。

5. `setMapTool(同一工具)` 不触发 `mapToolSet`（实测 mapToolSet 序列只有变化时
   才发）——重复点击已激活工具按钮时 QAction 勾选态会被自动翻转，回调必须显式
   恢复（工具条高亮任务同用此结论）。

6. 测试要点：磁盘缓存以 URL 为键，端到端验证必须给瓦片 URL 加随机 `?r=` 参数
   防命中上次缓存；临时慢速瓦片服务器用纯 stdlib 手工构造 PNG（端口 18765）。

## 验证

- `tmp_prefetch_e2e.py`（慢速服务器 + 冷缓存 + 对照无预热组）：
  - 初始渲染拉 ~12 张北京区域瓦片（正确瓦片号而非 `(8192,8191)`）；
  - 预热轮请求 +60（8 extent × ~6 瓦片，done=8）；
  - 平移一屏：对照 白屏帧=3（≈0.6s）/ 恢复 0.89s；预热 **白屏帧=0** / 恢复 0.22s。
- `tests/` 全套通过（仅剩 3 个基线失败：crash_logging ×2、tools_dock ×1，
  与本次改动无关）。
- 临时脚本（tmp_tile_server / tmp_prefetch_e2e / tmp_job_probe* / tmp_api_probe）
  验证后已清理。

## 遗留

- 快速多视口连续拖动仍会命中未预热的中间位置瓦片（±1 视口覆盖的是最终落点）；
  如需彻底消除可把邻居粒度降到半视口（8 → 16 extent），属于观感级增强。
- 配置级替代方案（未做）：换服务端 key / 调大磁盘缓存 / 降 zmax。
