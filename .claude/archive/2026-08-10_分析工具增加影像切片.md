# 分析工具增加「影像切片」

日期：2026-08-10
分支：dev

## 背景

分析工具树（ToolsDock）已有矢量瓦片导出，缺栅格/影像切分。用户要求加一个
「影像切片工具」。影像切片 = 把栅格影像切分为 XYZ 瓦片金字塔，标准算法是
QGIS 的 ``gdal:gdal2tiles``。

## 做了什么

| 文件 | 改动 |
|---|---|
| `app/core/domain/imagery_tiles/__init__.py`（新增） | 领域包，惰性暴露 `CreateImageryTileTask` |
| `app/core/domain/imagery_tiles/service.py`（新增） | `ImageryTileJob`（参数）+ `ImageryTileService`（submit 到 taskManager，可取消） |
| `app/core/domain/imagery_tiles/task.py`（新增） | `CreateImageryTileTask(QgsTask)`，worker 线程跑 `gdal:gdal2tiles`，`progress_updated` 报进度 |
| `app/ui/dialogs/imagery_tile.py`（新增） | `ImageryTileDialog`：输入栅格图层 / 缩放等级 min-max / 切片方案 / 重采样 / 网页查看器 / 输出目录；右算法描述；后台任务 + 进度条 + 完成/失败提示 |
| `app/ui/docks/tools_dock.py` | `_DIALOG_FACTORIES` / `_TOOL_TIPS` 加 `gdal:gdal2tiles`；「数据导出」组追加「影像切片（XYZ）」 |
| `app/ui/common/algo_desc.py` | `gdal:gdal2tiles` 兜底中文描述 |

## gdal:gdal2tiles 参数（QGIS 3.40 实测）

| 参数 | 类型 | 取值 |
|---|---|---|
| INPUT | raster | 栅格图层（传对象，同 BufferJob 约定） |
| PROFILE | enum | 0=Mercator 1=Geodetic 2=Raster |
| ZOOM | string | `"min-max"`（gdal2tiles `-z`） |
| VIEWER | enum | 0=All 4=None |
| RESAMPLING | enum | 0=Average 1=Nearest 2=Bilinear 3=Cubic 4=Cubic B-Spline 5=Lanczos 6=Antialias |
| OUTPUT | folderDestination | 输出目录 |

## 关键实现点

- **后台任务**：与 `tiles/task.py`（矢量瓦片）同构——QgsTask 工作线程跑
  `processing.run('gdal:gdal2tiles')`。跨线程进度不能直接投递到 QObject 槽
  （原生崩溃 0xC0000409），先接到 Python 方法再更新控件（沿用仓库既定模式）。
- **进度**：gdal2tiles 的 QgsProcessingFeedback 进度可能不精确（多数在完成前
  保持低位），但完成/失败由 `taskCompleted` / `taskTerminated` 信号收尾，分别
  提示成功（含输出目录）与失败（含异常）/ 取消。
- **INPUT 传图层对象**：同 `BufferJob`，避免 source 离开工程上下文无法重载。
- **打包**：纯 Python + 依赖已有 processing/GDAL provider，无新资源、无 spec 改动。

## 验证

- `py_compile` 全部通过。
- 探针端到端：构造 512×512 GeoTIFF → 建栅格图层 → ToolsDock 工厂构造对话框
  （标题「影像切片」、栅格图层入下拉框）→ 描述非空 → `task.run()` 产瓦片：
  Mercator z8-10=12 张、z10-12=82 张、Geodetic z4-6=3 张、Raster z2-4=336 张。
- 注意：极小栅格 + 极低缩放（如 64×64 在 z0-2）会被压到亚像素、不产瓦片，
  属 gdal2tiles 正常行为，非 bug。
