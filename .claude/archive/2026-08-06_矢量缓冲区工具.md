# 矢量缓冲区工具（ToolsDock → BufferDialog → BufferService）

日期：2026-08-06

## 背景

用户请求"@AnalyseDock 中再添加一个矢量缓冲区工具"，经 AskUserQuestion 澄清后确认：加到 **ToolsDock**（真正显示的"分析工具"dock，`app/ui/docks/tools_dock.py`），而不是 `AnalyseDock` 占位类。

## 做了什么

在分析工具树新增"矢量缓冲区"节点，点击弹出 `BufferDialog`，同步执行 `native:buffer` 并把结果图层加入工程：

| 文件 | 改动 |
|---|---|
| `app/core/domain/buffer/service.py` | **新增** `BufferJob` frozen dataclass + `BufferService.run()`（同步执行 native:buffer，返回结果图层） |
| `app/core/domain/buffer/__init__.py` | **新增**，导出 `BufferJob, BufferService` |
| `app/ui/dialogs/buffer.py` | **新增** `BufferDialog(BaseDialog)`：输入图层下拉框 / 缓冲距离 / 分段数 / 端点样式 / 连接样式 / 融合勾选 / 输出图层名 + 进度条 + 执行/关闭 |
| `app/ui/docks/tools_dock.py` | "矢量常规"下新增 `矢量缓冲区` 节点（`_code_="native:buffer"`），`_on_item_clicked` 分流打开 BufferDialog；顺带把静默 `except: pass` 改成 `logger.error` |

BufferJob 字段：`layer`（**图层对象**）、`distance`、`segments`、`dissolve`、`end_cap`（0圆/1平/2方）、`join_style`（0圆/1斜接/2平切）、`output_name`。对话框的样式下拉框索引即算法取值。

## 关键结论（真实 QGIS 3.40 实测）

- **`processing.run` 的 INPUT 必须传图层对象，不能传 `layer.source()`**：memory 图层（尤其处理结果）的 source 带 `uid=` 参数，离开工程上下文后按 source 字符串无法重新加载，报 `QgsProcessingException: Could not load source layer for INPUT: ... not found`。传图层对象则完全可用（valid、1 feature、geometryType 2=Polygon）。**注**：`native:writevectortiles_xyz` 的 `LAYERS` 参数用 `[{"layer": src}]` 字典反而能解析 source——两个算法解析 source 的方式不同，不能一概而论。
- **BufferService 设计为同步执行**（有意的取舍）：缓冲区对常规图层秒级完成，结果直接在主线程返回，对话框拿到图层后 `QgsProject.addMapLayer` + `canvas.refresh()`，无需跨线程移交；超大图层主线程会短暂阻塞。
- `QgsProcessingFeedback().progressChanged` → `QProgressBar.setValue` 可直接连接；tiny 图层上 0 个进度事件（进度条跳到 100）。
- `QgsMapLayer.VectorLayer` 存在，`layer.type() == QgsMapLayer.VectorLayer` 过滤矢量图层填下拉框；图层对象用 `combo.addItem(name, layer)` 存 itemData。
- 空工程（无矢量图层）点击执行 → `send("warning", "请先在工程中加载一个矢量图层")`，不崩溃。
- Processing 插件依赖：真实 QGIS app 已加载；离线探测环境需 `sys.path.append(plugins)` + `Processing.initialize()`。
