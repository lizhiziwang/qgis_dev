## 做了什么

### 1. 工具树点击复用对话框实例（设计缺陷修复）
- 原缺陷：每次点击工具节点都 `new Dialog().show()`，可无限叠加窗口。
- `ToolsDock` 新增 `self._dialogs: dict`（算法 code → 对话框实例）+ 模块级 `_DIALOG_FACTORIES`（懒 import 工厂）。
- 点击逻辑：已有实例且可见 → `raise_()` + `activateWindow()` 置前，不新建；已关闭 → 重新 `show()` 同一实例；无实例 → 工厂创建并缓存。`dlg.isVisible()` 包 `RuntimeError` 防御（C++ 对象销毁时清理）。
- `legacy/component/component/TreeTool.py` 的 `PGISTools` 同样加了 `self._dialogs` 守卫。

### 2. 最短路径分析工具（native:shortestpathpointtopoint）
- 领域服务 `app/core/domain/shortestpath/service.py`：`ShortestPathJob`（网络图层/起终点/路径类型/方向字段/速度字段/默认速度/输出名/输出路径）+ `ShortestPathService.run()`，返回 `(结果图层, 总代价)`；文件输出时从 gpkg 重新加载图层（复用 buffer/overlay 的文件输出修法）。
- 对话框 `app/ui/dialogs/shortest_path.py`：左参数右算法描述布局（同 buffer/overlay）；网络图层下拉**只过滤线图层**；方向字段/速度字段随网络图层联动填充；起终点支持**画布取点**（`QgsMapToolEmitPoint`，取点后恢复前一个 map tool）或手输 `x, y`；坐标自动从画布 CRS 变换到网络图层 CRS；输出文件路径行（gpkg/shp）。
- 工具树注册："矢量常规"下新增"最短路径分析"节点（`native:shortestpathpointtopoint`）；`algo_desc.py` 加兜底中文描述（注册表不可用时展示）。
- 复用守卫自动覆盖新工具（同一 code 只允许一个窗口）。

## 追加修复（2026-08-07）：网络图层下拉无数据

用户反馈：先开窗口后加线图层（路线/网格线图层），网络下拉依旧为空。根因：网络下拉只在对话框**构造时**填充一次；配合「工具树复用对话框实例」的机制，先开窗口再加载图层时下拉永远不刷新。

修法（`shortest_path.py`）：
- `__init__` 连接 `QgsProject.layersAdded` / `layersRemoved`（**不能用** `layerWillBeRemoved`——它在移除**前**触发，此时 `mapLayers()` 仍含该层，刷新无效），`_refresh_network_layers()` 重新填充并尽量恢复当前选择。
- 网络下拉保持**只过滤线图层**：探测确认 `native:shortestpathpointtopoint` 的 `INPUT.dataTypes()==[1]`（`TypeVectorLine`），算法只接受线图层；面图层跑进去只会得到 "There is no route from start point to end point."。
- 回归测试 `tests/ui/dialogs/test_shortest_path.py`：后加线图层出现、移除后消失、面图层不进下拉。注意 pytest fixture 里父窗口必须持引用，`ShortestPathDialog(QMainWindow(), ...)` 用临时父窗口会被 PyQt5 立即回收并连带销毁对话框（QComboBox has been deleted）。

## 追加（2026-08-07）：交互逻辑对齐 QGIS（后台执行 + 进度 + 取消）

用户反馈：最短路径在网格较大时同步 `processing.run` 阻塞主线程，窗口无响应。按用户要求把窗口交互改为**与 QGIS 原始 processing 对话框一致**——算法在后台任务里跑，窗口不阻塞，带实时进度条和取消按钮。

改动：
- **新增 `app/core/domain/shortestpath/task.py`**：
  - `ShortestPathFeedback(QgsProcessingFeedback)`：本构建**没有** `errorOccurred` 信号，改用覆写虚方法 `reportError(error, fatalError)` / `pushInfo(info)` 收集算法消息（如 "There is no route from start point to end point."）。
  - `ShortestPathRunnerTask(QgsProcessingAlgRunnerTask)`：QGIS processing 对话框自己用的后台任务类。新增 `progress_updated` 信号；`feedback.progressChanged` → 任务普通方法重发信号 → 对话框槽 `setValue`（**不能**把 progressChanged 直接连控件槽，本环境会原生崩溃 0xC0000409）。
- **`service.py`**：抽出 `build_shortest_path_params(job, output)` 供对话框/测试共用；`run()` 改用它。
- **`__init__.py`**：懒 `__getattr__` 暴露 `ShortestPathFeedback/ShortestPathRunnerTask`，非 GUI 导入不加载 qgis 依赖模块。
- **`shortest_path.py`**：`_on_execute` 不再同步跑，改为构造 context/feedback/alg/task 交给 `QgsApplication.taskManager().addTask()`；新增 `cancel_btn`（默认禁用，执行后启用，取消后变"取消中…"）；`closeEvent` 取消在跑任务；`taskCompleted` 主线程加载结果图层 + 提示总代价，`taskTerminated` 区分用户取消/算法失败（`feedback.isCanceled()` / `feedback.errors`）。输出：用户指定路径，留空走 `QgsProcessingUtils.generateTempFilename`（QGIS 处理临时目录，等价 "[Create temporary layer]"）。
- **`_ensure_processing_algorithm()`**：冷启动/非 GUI 场景 `Processing.initialize()` 兜底再取算法。

## 关键踩坑：QgsProcessingContext 裸指针 Segfault（本次最重）

`QgsProcessingAlgRunnerTask` 构造时保存 `mContext(&context)` —— 指向 `QgsProcessingContext` 的**裸指针**，worker 线程里使用。若 Python 里只当局部变量，`_on_execute` 返回后 GC 回收 wrapper → 删除 C++ 对象 → worker 线程悬垂指针 → **原生崩溃（无 Python 栈）**。
修法：`self._context = context` 让 context 存活到任务结束，`_on_task_completed/_on_task_terminated` 里清 None。同理 `_task` 在任务完成后被 QgsTaskManager 删除，handler 里**绝不能**再访问其成员，一律先置 None（本构建 `QgsTask` 也没有 `finished` 信号，用 `taskCompleted`/`taskTerminated`）。

## 追加（2026-08-07）：起点/终点画布标记

用户要求：选择起点和终点时在地图上显示出来。实现（`shortest_path.py`）：

- 每个输入框 `textChanged` → `_update_point_marker(key)`；可解析成坐标就在画布显示 `QgsVertexMarker`（起点红 / 终点绿，`ICON_RHOMBUS` 尺寸 14 笔宽 3），空/非法文本则隐藏。画布取点、手输、清除三条路径自动覆盖（取点/清除都会触发 textChanged）。
- 标记懒创建（`_point_marker`）：无画布（测试/无地图上下文）返回 None 不崩；标记坐标沿用输入框里的**画布坐标**，不做 CRS 变换。
- 对话框实例被工具树复用：`closeEvent` 里 `hide()` 两个标记，`showEvent` 里按当前文本恢复（重开窗口仍能看到已选点）。
- 标记 `C++` 对象随画布销毁 → 所有访问包 `RuntimeError` 防御，捕获后丢弃引用下次重建。
