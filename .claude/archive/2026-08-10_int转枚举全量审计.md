# 2026-08-10 app/ 全量检查 int→枚举残留（PyQt6 严格化）

## 背景

用户要求全量检查 `app/` 是否还有「把 int 字面量传给枚举参数」的 PyQt6 崩溃残留（上两个 bug 同属此类）。子代理通读全仓 + 本地针对性 grep + 运行时探针三管齐下。

## PyQt6 规则校准（实测）

- **int 传普通枚举（Qt 和 QGIS 枚举）→ TypeError**。在槽内未捕获 → 原生崩溃（exit 127）。
- **枚举成员 `|` 组合**（`QMessageBox.StandardButton.Yes | .No`）→ 仍可用（OR 结果同类型枚举）。
- **QGIS sip 枚举保留扁平类属性访问**：`QgsMapLayer.VectorLayer`、`QgsWkbTypes.PointGeometry`、`QgsVertexMarker.ICON_RHOMBUS`、`layer.VectorLayer`、`Qgis.*` 快捷方式全部正常 → **不是问题**。
- **枚举==int 比较、枚举作 dict key**：QGIS sip 枚举是 int 子类 → 正常，不是问题。
- `QVariant.String/Int/Double`（从 `PyQt6.QtCore` 导入）仍可用，`QgsField.type()` 返回 `QVariant.Type`。

## 发现并修复（2 处）

### 1. `app/ui/dialogs/query_builder.py:143`（真实崩溃）
`field.type() in (QgsField.String, getattr(QgsField, "Text", None))` —— **`QgsField.String` 在 4.2 已移除（AttributeError）**，在双击值列表槽里就是崩溃。
修复：→ `field.type() == QVariant.String`（补 `QVariant` 导入，删 `QgsField` 未使用导入）。

### 2. `app/core/domain/identify/service.py`（潜伏 bug）
`tool.identify(x, y, mode)` 传 `int mode=1` + float 坐标。4.2 签名改为 `identify(x: int, y: int, layerList=[], mode=...)`：
- x/y 必须是 int（float → TypeError）
- mode 必须是 `IdentifyMode` 枚举（int → TypeError）
- 注释写 TopDownAll 但值 1 实际是 TopDownStopAtFirst
修复：`mode=None` 默认 → `QgsMapToolIdentify.IdentifyMode.TopDownAll`，调用改 `int(x), int(y)`。

### 确认无需修改（子代理「存疑」项实测排除）
- `layer.type() == layer.VectorLayer` / `QgsMapLayer.*` / `QgsWkbTypes.*` 比较：QGIS sip 保留扁平访问，正常。
- `QVariant.Int/Double` 比较（attribute_dock.py、geom_cleanup.py）：正常。
- `g_type == 0/1/2`、`{0:"点"...}.get(geom_type)`：枚举是 int 子类，正常。
- `QgsUnitTypes.DistanceUnit(int)` 构造：正常。
- `find_feature.py:28` 真实识别路径：`self.identify(event.x(), event.y(), self.IdentifyMode.TopDownAll)` 在 4.2 正常（int 坐标 + 枚举）。
- 所有 QMessageBox / setSelectionMode / setEditTriggers / setSectionResizeMode / setRenderHint：已限定枚举，正常。
