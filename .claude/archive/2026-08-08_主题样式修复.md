# 主题样式修复：Dock 标题裁剪 + Combo 下拉按钮

日期：2026-08-08
分支：dev

## 背景

用户反馈"当前系统的样式设置存在小问题"：
1. **Dock 的 title 文本显示有问题**，文本下方被挡住约 10%。
2. **Qt 下拉选择框的下拉按钮都无法正常显示**。

两处都出在 `app/ui/common/theme.py` 的 QSS 上（窗口 chrome 走 `window_qss`，弹窗/通用控件走 `app_qss`）。

## 根因（离屏像素探测验证）

### Dock 标题裁剪
- QDockWidget 标题栏高度由原生样式按字体决定，本环境固定 **~22px**；`window_qss` 里
  `QDockWidget::title` 用了 `padding: 5px 8px`，把文本内容区压到 `22 - 10 = 12px`。
- 中文标题（如"分析工具"）按 12px 字号渲染时字形 ink 高约 12px，内容区只剩 **1px 余量**；
  字体回退/DPI 取整稍有差异，字形底部就被裁掉约 10%。逐字体探测：
  - `padding:5px` → content_h=12, ink_h=11, **spare=1（tight，任何取整差异即裁切）**
  - `padding:3px` → content_h=16, ink_h=12, **spare=4（安全）**
- `min-height` 对 `::title` 无效（标题栏高度不随 subcontrol 的 min-height 变，是原生样式定的）。

### Combo 下拉按钮
- `QComboBox::down-arrow` 用 CSS border 三角画箭头，但没给 `width/height`，盒模型没塌缩，
  三角在按钮内**偏上约 4px**（本环境箭头局部 y=6..10，按钮中心 y=12）。
- 修复 = 给 `down-arrow` 加 `width: 0px; height: 0px;` 把盒塌缩成 0，border 三角才会垂直居中；
  顺带给 `QComboBox::drop-down` 加 `background-color: transparent`。
- 附带确认：combo 聚焦时右侧边缘的蓝色是 `QComboBox:focus { border-color: input_focus }`
  的正常焦点环，非 bug，未改。

### Combo 箭头最终根因（第二轮回查）

用户反馈修复后箭头"依旧无法正常显示"。像素转储发现：**Qt QSS 不做斜角边框衔接**，
`border-left/right/top` 三角技巧在本构建里把 `border-top` 渲染成**实心方块**
（下拉按钮里出现一团 8×5 的黑块），不是三角形——所以无论是否加 `width:0;height:0`，
箭头始终是一块方块（用户看到的"无法正常显示"）。去掉自定义 `down-arrow` 让原生样式画，
在浅色主题是干净的三角，但 **dark 主题下原生箭头保持默认深色，在深色 `input_bg` 上完全
不可见**（这正是原作者用自定义 `down-arrow` 的原因）。

正确方案：**用 QPainter 现画一个主题色抗锯齿下三角 PNG**，QSS 里 `image: url(...)` 引用。
注意 QSS 的 `url()` 只认正斜杠绝对路径（`C:/...`），`file:///` URI 和带前导 `/` 的路径
都加载失败。

## 做了什么

| 文件 | 改动 |
|---|---|
| `app/ui/common/theme.py` `window_qss` `QDockWidget::title` | `padding: 5px 8px` → `padding: 3px 8px`（标题栏高不变 ~22px，内容区 12→16px，文本余量 1→4px）。加了行内注释说明原因 |
| `app/ui/common/theme.py` `app_qss` combo 段 | `QComboBox::drop-down` 加 `background-color: transparent`；`QComboBox::down-arrow` 改为 `image: url(生成的PNG)` + `width/height 10×8`（去掉 border 三角） |
| `app/ui/common/theme.py` 新增 `_down_arrow_url(color)` | 按主题 `menu_text` 色用 QPainter 画 10×8 下三角 PNG，存到系统 temp，按颜色缓存，返回正斜杠路径。带模块级 `_DOWN_ARROW_CACHE` |

## 关键结果（离屏像素验证，QGIS 3.40 python）

- **4 个主题**（light/dark/blue/green）逐一渲染验证：
  - Dock 标题：bar=22、content=16、ink=12、**spare=4 全部 OK**（改前 light spare=1 tight）。
  - Combo 箭头：**4 主题全部为干净三角形**（行宽 8→6→4→2 递减、中心 12.5 vs 目标 13），
    聚焦/失焦均正常（border 三角方案是 8×5 实心方块，中心即使居中也是方块）。
- `py_compile app/ui/common/theme.py` 通过。
- **GUI 回归**（`.tmp/run_gui_tests.py` bootstrap + QGIS python）：
  `tests/ui/docks/test_tools_dock.py -m gui` → **2 passed**。

## 备注 / 经验

- 标题栏高度由原生样式按字体决定且不随 `::title` 的 `min-height` 变 → 想给文本留余量只能
  减纵向 padding，加 padding/min-height 都没用。
- **Qt QSS 的 CSS border 三角技巧不生效**：Qt 不把边框做斜角衔接，`border-top` 配透明
  `border-left/right` 会渲染成实心方块而非三角形。要画三角只能用程序生成的 PNG
  （`image: url(路径)`），且 QSS `url()` 只认正斜杠绝对路径（`C:/...`），`file:///` URI、
  带前导 `/` 的路径都加载失败。
- 原生 combo 箭头在 windowsvista 样式下不跟 QSS `color`，dark 主题上保持默认深色不可见 →
  必须用主题色 PNG 覆盖。
- 离屏 `grab()` 对 QDockWidget 标题与 QComboBox 都能拿到真实像素；分析时**必须按主题取色
  （`t.menu_text`/`t.border`），不能用"深色像素"这类启发式**——dark 主题背景本身是深色，
  会把背景误判成文本。

## Combo 箭头弹出时翻转为上三角（第三轮回查）

用户反馈"箭头正常了，但是点击下拉之后应该变成上三角"。QSS 的 `image` 不能旋转，
翻转只能换 PNG。逐选择器探测（真实 `app_qss` + 离屏 grab，像素逐行计数判断三角朝向）：

| 选择器 | 结果 |
|---|---|
| `QComboBox::down-arrow:on { image: url(up) }` | **有效**：closed 下三角 → open 上三角 → closed 又回到下三角，4 主题全部 OK |
| `QComboBox:on::down-arrow { image: url(up) }`（Qt 文档写法） | **破坏渲染**：combo `grab()` 变 0×0/218×10、基础规则失效，不可用 |
| `QComboBox::down-arrow:open` | 与 `:on` 同族，未进一步验证（`:on` 已够） |

关键点：**`QComboBox::down-arrow:on`（子控件 + 伪状态）在本构建能翻转 `image`**，
而文档示例的 `QComboBox:on::down-arrow`（伪状态写在控件上）会破坏整个 combo 渲染
（可能触发 Qt 渲染路径 bug）。尺寸（width/height/margin）留在基础 `QComboBox::down-arrow`
规则里，`:on` 规则只覆盖 `image`（两规则同时命中时基础规则的尺寸仍生效）。

## 本轮改动

| 文件 | 改动 |
|---|---|
| `app/ui/common/theme.py` | `_down_arrow_url(color)` 重构为 `_arrow_url(color, up=False)`：按 `(颜色, 方向)` 缓存（`_ARROW_CACHE`），`up=True` 画上三角 PNG。`app_qss` combo 段新增 `QComboBox::down-arrow:on { image: url(上三角PNG) }` |
| `.tmp/` | 删除本轮 popup 探测脚本与 PNG |

验证：`py_compile` 通过；真实 `app_qss(t)` 在 light/dark/blue/green 4 主题下
closed→open→closed 往返均正确（down→up→down）。
