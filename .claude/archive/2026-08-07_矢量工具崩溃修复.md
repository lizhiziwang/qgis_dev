# 矢量分析工具（缓冲区 / 瓦片）进程崩溃修复

日期：2026-08-07
分支：dev
范围：`app/ui/dialogs/buffer.py`、`app/ui/dialogs/vector_tile.py`、`app/ui/docks/tools_dock.py`、`app/core/domain/buffer/`（新增，前置工作）

## 背景

用户在 ToolsDock 的"矢量常规"下使用"矢量缓冲区"（`native:buffer`）和矢量瓦片工具后，进程直接崩溃（0xC0000409），且没有任何 Python 报错日志。用户确认两个工具都崩，并指示"参考 legacy 中的分析工具"（`legacy/component/component/TreeTool.py` 可正常工作）。

## 根因（经阶段二分 + 对比探针定性）

崩溃是 Qt 信号回调把进度路由到**控件槽**造成的原生重入，不是业务代码异常：

| 探针 | 连线方式 | 结果 |
|---|---|---|
| stage_bisect A | `processing.run` + feedback 不接任何槽 | 安全 |
| stage_bisect B | `progressChanged` 直连 `bar.setValue` | **在 run 原生栈内崩溃**（B start 后无输出） |
| fix_verify B' | `progressChanged` `Qt.QueuedConnection` → `setValue` | run 完成，**投递时崩溃**（run done 后、processEvents 中断） |
| queued_test T1 | queued → 普通 Python 函数 `record` | 安全，199 个事件全部送达 |
| queued_test T2 | queued → `QProgressBar.setValue`（QObject 槽） | 投递时崩溃 |

结论：
1. `QgsProcessingFeedback.progressChanged` **直连或 QueuedConnection 路由到任何 QObject/控件槽都会原生崩溃**（0xC0000409，无 Python 异常可记日志）。
2. queued 投递到**普通 Python 可调用对象**是安全的。
3. 之前没复现是因为小图层（1 个要素）发出 **0 个 progress 事件**（直接跳 100）；200 要素图层 + 完整 MainWindow（canvas + layer-tree bridge）才复现。
4. 次要发现：本 build 的 `QgsTask` **没有 `finished` 信号**（AttributeError 被对话框 try/except 吞掉）；`QgsTaskManager` 在任务完成后会**删除 C++ 对象**，对话框持有的 `self.task` 变悬空指针，之后访问会 `RuntimeError`。

## 修复

### buffer.py
- 移除 `QgsProcessingFeedback` 的创建与 `progressChanged.connect(self.loading.setValue)`，进度条改为**手动** 0 → 100（不接任何进度信号）。
- `_run` 不再传 feedback（`self.buffer_service.run(job)`）。
- 执行路径保留仓库既定模式：`_on_execute` 只做校验 + 禁用按钮 + `QTimer.singleShot(0, lambda: self._run(job))`，把 `processing.run`/`addMapLayer` 推出 Qt 信号栈（与 `main_window._remove_layer` 同因）。

### vector_tile.py
- `self.task.progressChanged.connect(self.loading.setValue)`（永不触发的死连接）→ `self.task.progress_updated.connect(self._on_task_progress)`（普通 Python 方法，内部 `setValue`；跨线程 queued 投递到 Python 可调用对象安全）。
- `self.task.finished.connect(...)`（AttributeError）→ `taskCompleted` → 置 100、`taskTerminated` → 置 0。
- `except` 从 `print(e)` 改为 `logger.error(..., exc_info=True)`。

## 验证（`python-qgis-ltr.bat` + offscreen + 完整 MainWindow + 200 要素图层）

- 缓冲区：走真实 `_on_execute` → 延迟 `_run` → `addMapLayer` → `canvas.refresh()`。EXIT=0，进度 0→100，结果图层"缓冲区结果"入工程，canvas grab 正常。
- 瓦片：真实提交 `CreateTileTask`（worker 线程跑 `writevectortiles_xyz`），进度经 `progress_updated` → Python 方法到达 100，实际生成 `0/0/0.pbf` 等瓦片文件，全程无崩溃。
- 两个探针均在 `.tmp/`，验证后已全部清理。

## 未竟事项 / 观察
- 瓦片任务失败时（run 返回 False）也会触发 `taskCompleted` → 进度条到 100；成功/失败未区分。当前 run 内异常存进 `task.exception`，UI 未消费——如需要可在 `finished` 虚方法里区分上报。
- `vector_tile.py` 的"执行"按钮未在运行期禁用（`_init_ui` 里是局部变量），连续点击会重复提交任务；如需可把按钮存为 `self.execute_btn`。
