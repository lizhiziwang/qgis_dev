# 会话归档：影像切片修复、优化与 MBTiles 新工具

日期：2026-08-10
分支：dev

## 做了什么

本会话围绕「影像切片」工具展开，共四段任务：

1. **修复窗口未响应**（任务 #12）
   `native:tilesxyzdirectory` 执行时影像切片窗口一直未响应（进程退出码 127）。
   三个探针定位：`_probe_hang`（taskManager 路径崩溃）→ `_probe_isolate`
   （不连信号仍崩溃）→ `_probe_thread`（普通 `threading.Thread` 跑同一
   `processing.run` 稳定）。根因：该算法内部用 `QgsMapRendererSequentialJob`，
   经 `QgsTaskManager` 后台线程运行生命周期不兼容。
   修复：`CreateImageryTileTask` 从 `QgsTask` 改为 **QObject + 普通线程**
   （`start()` 启动 daemon 线程，`cancel()` 调 `feedback.cancel()`）；
   `service.submit` 不再提交 taskManager；对话框连信号后 `start()`。

2. **性能优化**（用户反馈「算法好慢」）
   读 QGIS 源码 `qgsalgorithmxyztiles.cpp` 确认：算法不是切影像，而是逐瓦片
   重渲染**所有可见图层**（探针证实矢量面被渲染进瓦片）。实测对比（4096² 影像
   + 矢量面，0-12 级，75 瓦片）：

   | 方案 | 耗时 |
   |---|---|
   | METATILESIZE=4（现状） | 2.73s |
   | METATILESIZE=10 | **0.46s**（约 6 倍提速） |
   | gdal:gdal2tiles | 3.83s（反而更慢） |

   改动：`METATILESIZE` 4→10；新增 `estimate_tile_count()`（与算法
   `getMetatiles` 同一公式）+ 对话框执行前瓦片数预警（>2000 弹窗确认）。

3. **新增「影像切片（MBTiles）」工具**（任务 #13-15）
   `native:tilesxyzmbtiles` 输出单个 .mbtiles 文件（SQLite 内嵌 XYZ 瓦片
   金字塔，便于分发）。新增 `app/core/domain/imagery_mbtiles/` 包
   （service/task）、`app/ui/dialogs/imagery_mbtiles.py` 对话框、
   `save_file()` 辅助、工具树注册、兜底描述。MBTiles 固定 256×256、按 TMS
   存储；参数为 EXTENT/ZOOM_MIN/ZOOM_MAX/DPI/BACKGROUND_COLOR/ANTIALIAS/
   TILE_FORMAT/QUALITY/METATILESIZE/OUTPUT_FILE。

4. **MBTiles 生成网页预览 HTML**
   算法无内置 HTML 且浏览器读不了 SQLite。方案：切片成功后把瓦片从 mbtiles
   解出成 `{文件名}_preview/{z}/{x}/{y}.png`（TMS→XYZ 换算
   `xyz_y = 2^z - 1 - tms_y`），再生成 Leaflet `index.html`（相对路径瓦片，
   双击可预览）。对话框加「生成网页查看器（HTML）」复选框。

## 关键结果

- 崩溃根因定位准确：QgsTaskManager + native 算法 → 改普通线程后
  `_probe_real_path` exit 0、瓦片产出、日志齐全、主线程心跳正常。
- 性能：METATILESIZE 4→10 同量瓦片快约 6 倍，且 gdal2tiles 反而更慢，
  不需要换算法。
- MBTiles 全链路探针：对话框冒烟实例化正常、任务 0.21s 完成、产出合法
  .mbtiles（metadata + tiles 表、9 行瓦片、元数据正确）、日志 15 条全收到。
- HTML 预览探针：9 瓦片完整解出、TMS→XYZ 换算 0 不匹配、index.html 有效。
- 抽出共享 `ProcessingLogFeedback`（`imagery_tiles/feedback.py`），两个切片
  工具共用，无残留 `_ImageryTileFeedback` 引用。
- 全部 `py_compile` 通过，探针文件均已清理。

## 遗留事项

- MBTiles 算法经 `QgsTaskManager` 崩溃未单独复测——与 directory 版同源，已
  沿用普通线程方案规避，风险低。
- `imagery_mbtiles` 与 `imagery_tiles` 两个并行包有少量重复（任务类骨架），
  后续可考虑进一步泛化合并为共享基类。
- 瓦片数预警阈值 2000 为固定值，可后续做成可配置。
