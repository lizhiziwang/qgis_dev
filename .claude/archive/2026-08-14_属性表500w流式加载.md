# 2026-08-14 属性表 500w 级矢量数据卡死修复（流式迭代器改造）

## 背景

用户反馈：`app/ui/docks/attribute_dock.py` 属性表本应流式加载（先 2000 条、后续
滚动加载），但 500w 级矢量数据会**直接卡死程序**。

## 根因（探针逐项确认）

冻结有两个叠加来源，全在 `PagedAttributeTableModel`：

1. **`_refresh_totals()` 在 UI 线程同步收集全部匹配 ID**：`sorted(f.id() for f in
   self.layer.getFeatures(request))` 把 500w 个 ID 一次性塞进 `self.all_ids`。
   500w 级图层即 UI 线程阻塞数十秒。
2. **`batch_size = 总量 × 20%`**：500w 图层首屏就是 100w 条，同样同步拉取卡死。

探针确认的 QGIS 4.2 API 事实：
- `QgsFeatureRequest.setOffset` **不存在**（代码注释没错）——这是原设计要预收集
  全部 ID 当分页索引的原因。
- `layer.featureCount()`（无过滤）O(1) 即时返回；`dataProvider().featureCount()` 同理。
- **`QgsFeatureIterator` 支持 `next()` 且断点续取有效**（连续 `next()` 依次返回
  1,2,3,...），带过滤的表达式同样可流式。
- 带过滤表达式的总数必须遍历才能知道（`featureCount()` 只给无过滤总数）。
- `QgsVectorLayer.countFeatures()` 和 `QgsVectorLayer.feature()` 在本构建均不存在
  （记忆里的 API 名错了，实为 `featureCount()`）。
- `QgsFeatureRequest` 无 `setNoGeometry` 方法，要用 `setFlags(Flag.NoGeometry)`。

## 做了什么

**`app/ui/docks/attribute_dock.py`**（核心改造）：
- 删除死代码 `FeatureLoaderThread`（预收集 ID 的旧线程，从未被使用，且正是被
  淘汰的方案）+ `math`/`QThread` 导入。
- 新增常量 `STREAM_BATCH = 2000`（大图层每批固定 2000，首屏即 2000，与用户
  期待一致；不再用 20% 这种随总量放大的批次）。
- `PagedAttributeTableModel` 改为**持有一个 `QgsFeatureIterator` 流式续取**：
  - 去掉 `self.all_ids`；`load_more()` 每次 `next()` 拉 `batch_size` 条。
  - `_fast_total()`：无过滤（`where` 为 `1=1`）时 `featureCount()` 快路径 O(1)；
    带过滤/show_ids 时总数未知（`total_known=False`），流式结束（迭代器耗尽）
    后补齐真实总数。
  - `batch_size`：总量已知且 ≤ 阈值 → 一次全量；否则固定 `STREAM_BATCH`。
  - `has_more` 改为 `not self._exhausted`（不再依赖 loaded_count < total）。
  - **边界探测（关键）**：总量恰好是 batch 整数倍时迭代器恰好在批次边界耗尽，
    只拉满 batch 就停永远探测不到末尾 → 批次拉满后再 `next()` 一次判断下一条，
    探测出的要素暂存 `_lookahead` 归入下一批。
  - 迭代中异常（图层被外部改动使游标失效）标记耗尽，避免死循环。
- `PagedAttributeTableWidget._refresh_load_state()`：新增 `total_known` 分支——
  过滤场景先显示"已加载 X 条…"，流式结束补齐总数后显示"共 N 条（已全部加载）"。

**`tests/ui/docks/test_attribute_dock.py`**：随新语义重写。旧断言（20% 批次、过滤
即知总数）本身就是 bug 的一部分。新测试 monkeypatch 同时调小
`DYNAMIC_LOAD_THRESHOLD` 和 `STREAM_BATCH`，让 120 条小图层走分批路径；新增
`test_widget_filter_status_unknown_total` 覆盖过滤后总数渐进显示。

## 关键结果

真实 QGIS 4.2 环境复刻全部测试场景（含新增）通过，性能对比：

| 操作 | 耗时 |
|---|---|
| 新方案 20 万要素初始化 + 首屏 2000 条 | **0.003s** |
| 新方案第二屏 2000 条 | 0.003s |
| 旧方案预收集 20 万 ID | 0.301s（且 500w 级线性放大到卡死） |

验证覆盖：分批语义、整数倍边界耗尽、空图层、小图层全量、超阈值分批、筛选重置
（总数未知流式）、show_ids 子集、widget「加载更多」按钮与状态文本、过滤后状态
渐进显示、AttributeDock 构造 + 右键选中刷新画布、MainWindow 方法冒烟、编辑
setData 回归（流式加载的行仍可改属性并同步到图层）。

## 遗留事项

- 过滤/show_ids 查询的总数在流式结束前显示为"已加载 X 条…"（无法免遍历获知），
  流式完成后补齐；无过滤大图层仍即时显示真实总数。
- 流式迭代器跨多个 load_more 保持打开，若其间图层结构大改（provider 游标失效）
  会在下一次加载时标记耗尽并停止追加（已有保护），不崩溃。
- `app/ui/flow_editor/` 仍为 git 未跟踪模块。
