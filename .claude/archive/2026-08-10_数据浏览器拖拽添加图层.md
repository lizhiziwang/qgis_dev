# 2026-08-10 数据浏览器拖拽添加图层

## 问题

用户：`@app/ui/main_window/browser_dock.py` 目前只有双击才能添加图层，能不能把拖拽添加图层也加进来。

## 方案

两层改动，复用双击的 `_add_layer_to_project` 路径（保证进"数据图层"分组 + 设置 `path_c`）：

1. **浏览器侧（`app/ui/main_window/browser_dock.py`）**：视图开启拖出
   ```python
   self.view.setDragEnabled(True)
   self.view.setDragDropMode(QAbstractItemView.DragDropMode.DragOnly)
   ```
2. **画布侧（`app/ui/main_window/main_window.py`）**：`_build_canvas()` 里 `canvas.installEventFilter(self)`，新增 `eventFilter` + `_on_canvas_drop`：
   - `DragEnter/DragMove/Drop` 且 `QgsMimeDataUtils.isUriList(mime)` 为真 → 拦截；
   - Drop 时 `decodeUriList` 逐个建层（vector→`QgsVectorLayer`，raster→`QgsRasterLayer`），provider=="ogr" 时 `path_c = u.uri`，再 `_add_layer_to_project`；
   - 非图层 URI（普通文本/外部文件）`return False` 放行原生。

原生 `QgsMapCanvas` 的 drop 会把图层直接挂工程根节点，不进"数据图层"分组、也不设 `path_c`，与双击行为不一致，所以拦截。

## 关键事实（QGIS 4.2，均探针实测）

- `QgsBrowserModel.mimeData([layerIndex])` 对 `QgsLayerItem` 产出 `application/x-vnd.qgis.qgis.uri`；`isUriList`/`decodeUriList` 往返正常。
- `QgsMimeDataUtils.Uri` 构造签名变了：不接受位置字符串，最稳是 `Uri(QgsMapLayer)`；`Uri.filePath` 对文件图层也是空串，`uri` 才是文件路径。
- `QgsLayerItem.mimeUri()` 在 4.2 已废弃。
- **`eventFilter` 在 `__init__` 期间就会触发**：`_build_canvas` 里 `installEventFilter` 后、`self.canvas` 赋值前有事件送达 → 直接访问 `self.canvas` 会 AttributeError → 槽路径 native 崩溃（exit 127 无 traceback）。修复：`getattr(self, "canvas", None) is watched` 守卫。
- PyQt6 `QDropEvent(pos: QPointF, actions: Qt.DropAction, ...)`。

## 验证

- 新增 `tests/ui/main_window/test_browser_drag_drop.py` 6 例：视图 dragEnabled/DragOnly、drop 进工程、ogr `path_c`、进"数据图层"分组、DragEnter/Move 接受且不加图层、非 URI 拖拽放行。
- 端到端探针（真实 MainWindow + 合成 QDropEvent）：drop → 图层进工程 + `path_c` == 文件路径。
- 全量测试：**171 passed, 1 skip（fastapi），EXIT=0**（原 165 + 新增 6）。
- `py_compile` 通过；探针已删。
