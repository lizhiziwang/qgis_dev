# 数据质检工具：表格勾选 + OGR SQL 引号修复

## Context（为什么改）

用户反馈「通用工具内的数据质检工具」两个 bug：

1. **表格栏无法进行勾选** —— 质检树状表格里的 checkbox 被 `setEnabled(False)`
   锁死，用户没法勾选要执行的质检项。
2. **点击确认报错** —— 跑质检时 GDAL 连报 6× `ERROR 1: Type mismatch or
   improper type of arguments to IN operator.`

根因两条，各自独立：

- 勾选锁死是 UI 层直接写死禁用，且当时根本没有"勾选 ↔ 执行"的语义。
- SQL 错误在 `DataValueCheck.build_where`：值域值（如地类 `030100` 带前导零）
  没按字段类型加引号，直接拼成 `"DI_LEI" not in (030100,...)`。OGR 把裸数字当
  数值/列名解析，字符串编码字段（GDB 里 DI_LEI 等全部是 QString）触发类型不匹配；
  且前导零在数值语境被丢弃，会造成值域错配。此外 `_update_item_status` 用
  `node.get("id") == check_id` 比较，JSON 的 id 是 int、`CheckParam.check_id` 是
  str，恒不等，跑完的状态永远写不回树。

## 方案

### 1. `app/core/domain/check/builtin/value_check.py` — 按字段类型引号（Fix 1）

`build_where` 逐字段取真实 `QgsField` 类型（`layer.fields().indexOf` + `.at().type()`，
拿不到时保守按字符串）：

- 数值字段（Bool/Int/UInt/LongLong/ULongLong/Double/Float）：值能 `float()` 解析就
  保持裸字面量；否则该值对这个字段无比较意义 → 跳过。
- 其余（字符串/日期）：加单引号，内嵌单引号用 `''` 翻倍转义。

输出形如 `"DI_LEI" not in ('030100','030200',...)`，空串值域（如林种含 `""`）被
过滤掉，不再产生 `not in ('')` 误判。旧测试兼容：`_field_type` 用 try/except 兜底，
MagicMock layer 走 QString 分支。

### 2. `app/ui/dialogs/check_viewer.py` — 勾选 ↔ isApply（Fix 2）

- `_refresh_display`：checkbox 去掉 `setEnabled(False)`，`stateChanged` 接
  `_on_toggle_apply`。
- 新增 `_on_toggle_apply(item, state)`：勾上 → 节点 `isApply=1` 且**祖先联动勾上**
  （含根节点）；取消 → 子孙联动取消。这一步是用户"勾了还弹请先勾选"的直接根因：
  `_start_check` 按 `isApply==1 且所有祖先勾选` 收集，而默认 JSON 根节点
  `isApply=0`，勾叶子不联动的话根恒为 0 → 永远收集不到。辅助方法
  `_find_ancestors` / `_set_descendants_apply` / `_sync_checked_flags`（联动后
  把表格 checked 重新对齐再 `_refresh_display`）。
- `_start_check`：只收集 `isApply==1` **且所有祖先勾选**的叶子（`_collect_params`
  加 `enabled` 参数随层递归）；一个都没勾 → `QMessageBox.warning("请先勾选要执行的质检项")`
  return。
- `_update_item_status`：id 比较统一转 `str`，修 int vs str 恒不等。

## 追加：质检过程日志 + 进度条（2026-08-21）

用户要求「数据质检的过程需要加上日志和进度」。

### 改 `app/ui/dialogs/check_viewer.py`

- **进度条**：`_setup_ui` 表格与底部按钮之间加 `QProgressBar#loading`
  （闲置 0）；`_start_check` 运行时按质检项数设 range `(0, total)`，每项跑完
  `setValue(i)`，跑完复位 0。每项更新后调 `QApplication.processEvents()` 强制
  重绘（splash 同款修法），否则同步阻塞跑质检期间进度条 / 日志面板不刷新。
- **日志**（沿用仓库 `logger.info` 操作日志惯例，走日志面板）：
  - 开始：`数据质检开始：数据源=%s，共 %d 项质检`
  - 逐项：`质检执行 i/N：<质检名>` → `质检通过/不通过：<质检名>（不通过 %d 条）`
  - 异常：`logger.error("质检执行失败：%s（%s）：%s", ..., exc_info=True)`，计入不通过
  - 完成：`数据质检完成：共 %d 项，通过 %d，不通过 %d`
  - 结束 messagebar：`send("success", "数据质检完成：共 X 项，通过 Y，不通过 Z")`
- **防重入**：运行中 `confirm_but.setEnabled(False)`，finally 恢复；单条失败不中断
  整批。

### 追加：质检结果回显表格（2026-08-21）

用户要求「数据质检的结果也要回显到质检窗口的表格上」。原 `_update_item_status`
只写 JSON 节点，而 `_refresh_display` / 显示未通过项过滤都读 `all_items` 里
**加载时快照**（`pass`/`noPassCount`）→ 跑完表格永远是旧值「通过 / 0」。

改 `app/ui/dialogs/check_viewer.py`：

- `_update_item_status`：抽 `_find_json_node(check_id)`（str/int id 比较）找到节点，
  写 `isPass`/`noPassCount` 后**同步对应 all_items 快照**（按 `original_item is node`
  定位），表格即可回显。
- 新增 `_aggregate_results`：叶子结果向上聚合——中间节点（属性质检/值域范围/根）
  `isPass`=全部子项通过、`noPassCount`=子孙叶子错误数之和（未勾选叶子按通过参与）；
  同步中间节点快照。`_start_check` 完成后先聚合再 `_refresh_display`。
- `_show_context_menu`：「查看错误数据」仅对叶子（`isCheckItem`）显示，聚合出
  "不通过"的中间节点没有 checkParam，不再误弹属性表。
