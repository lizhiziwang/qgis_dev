## 做了什么

### 领域服务 `app/core/domain/reproject/service.py`
- `ReprojectJob`（输入图层对象 + 目标坐标系 + 输出名/路径）+ `ReprojectService.run()`，同步执行 `native:reprojectlayer`，返回结果图层（调用方负责加入工程）。
- 复用 `copy_with_widened_string_fields`（GDB 字符串字段长度脏数据修正，同 buffer/overlay）；文件输出时从 gpkg/shp 重新加载图层（同 buffer 的文件输出修法）。
- 目标坐标系无效抛 `ValueError`。

### 对话框 `app/ui/dialogs/reproject.py`
- 布局同 buffer/overlay（左参数右算法描述）；**目标坐标系用 `QgsProjectionSelectionWidget`**（与 QGIS 原生重投影对话框一致），默认工程 CRS（无效时 EPSG:4326）。
- 输入下拉随工程 `layersAdded`/`layersRemoved` 动态刷新（沿用最短路径对话框的经验，避免"先开窗口后加图层无数据"）。
- 同步执行，`QTimer.singleShot(0)` 出信号栈再跑（Qt 信号回调里重入原生渲染会 0xC0000409 崩溃，见 buffer 注释）。

### 注册
- 工具树"矢量常规"下新增"重投影"节点（`native:reprojectlayer`）+ 懒加载工厂 + 实例复用守卫自动覆盖。
- `algo_desc.py` 加兜底中文描述（注册表不可用时展示）。

## 踩坑

- **对话框 execute 测试的 Processing 依赖**：`processing.run` 在测试环境里若 Processing 插件未加载会报 `QgsNotSupportedException: Processing plugin has not been loaded`。真实 app 启动时已 `Processing.initialize()`，但 pytest 环境不保证——跑对话框执行测试前必须手动 `Processing.initialize()`（服务测试通过 fixture 里初始化，对话框测试单独加）。表现为**测试顺序相关**：单独跑 reproject 目录（服务测试先初始化）通过，先跑 dock 测试再跑对话框就挂。
