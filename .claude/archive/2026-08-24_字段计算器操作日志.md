# 字段计算器：操作日志

## Context（为什么改）

字段计算器（复用 QGIS 内置 `QgsFieldCalculator`，见
[[2026-08-24_属性表字段计算器复用QgsFieldCalculator]]）成功后，用户要求
「字段計算也要记录日志」——字段计算操作要写入操作日志（LogDock 渲染的
`logs/app.log`）。

## 关键约束

探针实测：`QgsFieldCalculator` 的 Python 可见自有成员**只有** `changedAttributeId`
信号，不暴露表达式/输出字段（`expression`/`outputFieldName`/`setExpression` 等
全部不存在）。→ 日志无法记录"计算了什么表达式"，只能按**图层字段状态变化**
记录：图层名 + 字段数 A→B + 新增字段名。

## 改动

- `app/ui/docks/attribute_dock.py`
  - 顶部加 `from app.infra.logging import get_logger` + 模块级
    `logger = get_logger(__name__)`（照 `buffer/service.py` 模式）。
  - `_field_calc`：对话框前取 `before_names`；Accepted 后取 `after_names`，按
    差集分支记录：
    - 有新增字段 → `字段计算完成：图层=%s，新增字段 %s（字段数 %d→%d）`
    - 无新增字段 → `字段计算完成：图层=%s，更新已有字段（字段数 %d）`
    （无取消日志，Cancel 直接 return，不产生记录。）
  - 记录仍在 `_sync_edit_buttons()` / `model.reload_fields()` 之前执行。

## 测试

`tests/ui/docks/test_attribute_dock.py`：
- `test_field_calc_accept_refreshes_model` 增加 caplog 断言（新增字段分支：
  日志含 `字段计算完成` 与 `CALC`）。用 `caplog.at_level(INFO, logger=...)`
  包裹——模块 logger 由 `get_logger` 设了 level 且 `propagate=True`，冒泡到
  root，caplog 能捕到。
- 新增 `test_field_calc_update_existing_logs`（更新分支：加字段又立刻删掉，
  净字段数不变 → 日志含 `更新已有字段`）。

## 已知边界

- 日志不含表达式内容（对话框不暴露）——如需记表达式，得在调用方自建
  表达式字符串，目前没有这个需求来源。
