# 修复 GDAL 对话框两个 UI 反馈：最大高度 + 描述渲染

## Context（为什么改）

用户在接入 59 个 GDAL 算法到工具树后，又提了两个 UI 反馈：

1. 「gdal所有的算法的最大高度改为和mainwindow一致」—— `GenericAlgDialog`
   只设了 `setMinimumSize(760, 620)`，没有 maxHeight，sizeHint 实测 927px，
   比 MainWindow 默认 800px 还高，弹出后超出主窗口范围
2. 「对话框内的算法描述为什么 gdal:cliprasterbymasklayer 都是这种命令」——
   算法右侧说明区直接展示 `<p>gdal:cliprasterbymasklayer</p>` 这种「裸 code
   命令」，没有任何人类可读的中文描述

## 探针 / 根因（关键观察）

### Issue 1：最大高度

读 `app/ui/main_window/main_window.py:114`：

```python
self.setGeometry(100, 100, 1200, 800)  # MainWindow 默认 1200x800
```

读 `app/ui/dialogs/generic_alg.py:94`（修复前）：

```python
self.setMinimumSize(760, 620)  # 没有 maxHeight
```

探针实测（修复前）：`GenericAlgDialog.sizeHint() = 1117x927`，超过 mainwindow 800。

`tools_dock.py` 调用 `factory(self.topParent)` 把 `MainWindow` 传为 dialog 的 parent，
所以可以在 `__init__` 里沿父链找 `QMainWindow` 取高度。

### Issue 2：描述渲染

探针（在真实 QGIS 4.2 下跑 `_probe_ui.py`）拿 `QgsApplication.processingRegistry()`
查 6 个算法的 `shortHelpString()`：

| algo_id | displayName | help length |
|---|---|---|
| gdal:cliprasterbymasklayer | 'Clip raster by mask layer' | **0** |
| gdal:cliprasterbyextent | 'Clip raster by extent' | **0** |
| gdal:warpreproject | 'Warp (reproject)' | **0** |
| gdal:translate | 'Translate (convert format)' | **0** |
| gdal:buffer (注：算法 id 不存在) | — | alg is None |
| native:buffer | 'Buffer' | **611** ← native 有真实帮助 |

**根因**：QGIS 4.2 在本环境下，**所有 `gdal:*` 算法的 `shortHelpString()` 都返回
空字符串**（注册表能拿到 alg，displayName 对，但 help 文本没装上——可能 i18n
资源不全或 help bundle 缺失）。

`algorithm_description_html` 旧逻辑：

```python
if help_html:        # 空字符串走 False
    return title + help_html
# 没有 help → 落到 _ALGO_FALLBACK_DESC.get(code, f"<p>{code}</p>")
# _ALGO_FALLBACK_DESC 里没有 gdal:* 兜底 → 展示「裸 code 命令」
```

## 方案

### Fix 1：dialog 最大高度 = 父 QMainWindow 高度

`app/ui/dialogs/generic_alg.py`：

```python
def __init__(self, parent=None, algo_id: str = "", title: str = "") -> None:
    ...
    self.setMinimumSize(760, 620)
    max_h = self._resolve_max_height(parent)
    if max_h:
        self.setMaximumHeight(max_h)   # ← 关键约束
    ...

def _resolve_max_height(self, parent) -> Optional[int]:
    """走父链找 QMainWindow 拿真实高度；找不到退到 QScreen - 80（任务栏留白）。"""
    node = parent
    while node is not None:
        if isinstance(node, QMainWindow) and node.height() > 0:
            return node.height()
        node = node.parentWidget() if hasattr(node, "parentWidget") else None
    screen = QGuiApplication.primaryScreen()
    if screen is not None:
        return max(400, screen.availableGeometry().height() - 80)
    return None
```

`PyQt6.QtGui.QGuiApplication` 和 `PyQt6.QtWidgets.QMainWindow` 提到模块顶部 import，
避免函数内 import 引起的 linter 警告。

### Fix 2：GDAL 算法描述兜底

`app/ui/common/algo_desc.py`：

1. **新增 `_GDAL_FALLBACK_DESC`**：59 个 `gdal:*` 算法全部手工写中文描述
   （按 `tools_dock._GDAL_ALGORITHMS` 的 6 个分组排版：栅格分析 18 / 栅格地形
   11 / 栅格数据源 11 / 栅格元数据 3 / 矢量分析 11 / 数据导出 4 = 58，加上
   `gdal:convertformat` 在「数据源」末尾 1 个 = 59 个全补齐）
2. **`_ALGO_FALLBACK_DESC` 合并 `_GDAL_FALLBACK_DESC`**：

   ```python
   _ALGO_FALLBACK_DESC: dict[str, str] = {
       **_GDAL_FALLBACK_DESC,    # 优先查 GDAL 中文描述
       "native:writevectortiles_xyz": (...),
       ...
   }
   ```

3. **`algorithm_description_html` 三段式兜底**：

   ```python
   if alg is not None:
       name = alg.displayName()
       help_html = alg.shortHelpString()
       if help_html:
           return title + help_html
   # help 空：至少展示 displayName，避免「裸 code」
   fallback = _ALGO_FALLBACK_DESC.get(code)
   if fallback is not None:
       return fallback
   if name:
       return f"<h2>{name}</h2>...内部 code：<code>{code}</code>..."
   return f"<p>{code}</p>"
   ```

   即便 59 个里有遗漏，也会 fallback 到 displayName + 「未提供详细说明」，
   不会再出现「裸 code 命令」。

## 关键 API 备忘

- **PyQt6 顶部 import**：`QGuiApplication` 在 `PyQt6.QtGui`，`QMainWindow` 在
  `PyQt6.QtWidgets`；函数内 import 会触发 linter「无法解析导入」警告，建议提到
  顶部
- **`QWidget.parentWidget()` 走父链**：返回的是最近一个 QWidget 父级；不是
  QObject 父级；QDialog 有 QWidget parent 时，dialog.parent() 直接拿到
- **QGIS processing help 为空**：本环境下所有 `gdal:*` 都返回 `""`，可能是
  QGIS 4.2 帮助资源未完整装载。如未来官方提供 help，自动会优先用真实 help，
  本次中文描述只是兜底

## 风险与限制

- **动态调整**：当前实现是 `__init__` 时一次性 `setMaximumHeight(mainwindow.height())`，
  mainwindow 后续 resize 不会同步更新 dialog 上限。对工具对话框使用场景够用
  （dialog 临时打开，mainwindow 不会一边开着 dialog 一边改高度）；后续如需
  跟随可在 `MainWindow` resize 事件里重新调
- **测试 `processing_ready` fixture**：必须放在 test 函数签名里，不能在模块
  顶层调 `Processing.initialize()`（那时 `qgis_app` fixture 还没执行 initQgis，
  processing registry 是空的，连 `native:buffer` 都查不到）
- **中文描述是手写**：59 条 ≈ 200 行 HTML（每条 2-6 句），后续如需维护可拆到
  `app/ui/common/algo_desc_data.py` 单独放；当前为了一次到位全部放在
  `algo_desc.py` 的 `_GDAL_FALLBACK_DESC` 常量里
